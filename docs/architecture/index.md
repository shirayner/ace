## 组件详解

### 1. Skills（智能技能层）

ACE 的核心能力封装，按需触发。

#### 触发机制

```
用户输入 → Skill description 匹配 → 加载 SKILL.md → 执行
```

#### 四层加载模型

| 层级 | 内容 | 预算 | 加载时机 | 示例 |
|------|------|------|---------|------|
| **Metadata** | name, description | ~100 词 | 始终在上下文 | `name: coding` |
| **Trigger** | 触发条件 | ~50 词 | 始终在上下文 | `关键词：实现、修复` |
| **Cognitive** | 核心协议 | <500 行 | Skill 触发时 | OODA 循环、意图路由 |
| **Resource** | 深度参考 | 不限 | 按需加载 | `implement-guide.md` |

#### Skills 对比

| Skill | 核心能力 | 触发场景 | 理论来源 |
|-------|---------|---------|---------|
| **auto-goal** | 自主完成目标 | 复杂任务、多步骤项目 | OODA、Cynefin、认知负荷 |
| **coding** | 代码域认知协议 | 编码、测试、审查 | Clean Code、TDD、代码审查 |
| **skill-creator** | 创建新 Skills | Skill 开发、Eval | Anthropic 最佳实践 |
| **skill-optimize** | 优化现有 Skills | Skill 调优 | 信息论、认知科学 |

### 2. Rules（认知规则层）

通过 `CLAUDE.md` 和 `@` 引用机制，将规则注入每次对话。

#### 加载机制

```
~/.claude/CLAUDE.md
  ├── @~/.claude/rules/ace/thinking.md
  ├── @~/.claude/rules/ace/clean-code.md
  └── ...
```

Claude Code 启动时自动解析 `@` 引用，将规则文件内容加载到上下文。

#### 8 条规则分类

| 类别 | 规则 | 加载时机 | 作用 |
|------|------|---------|------|
| **认知框架** | thinking | 始终 | 六字原则 + 域感知 |
| **代码规范** | clean-code | 始终 | Clean Code 六原则 |
| **代码规范** | code-quality | 编辑代码文件时 | 质量检查清单 |
| **工作流** | reporting | 始终 | 自动报告输出 |
| **工作流** | task-recovery | 始终 | 任务中断恢复 |
| **工作流** | context-hygiene | 始终 | 上下文管理 |
| **工作流** | memory-policy | 始终 | 记忆保存策略 |
| **交互** | interactive-clarify | 始终 | 用户交互规则 |

### 3. Memory（记忆系统）

跨会话持久化开发者信息和项目上下文。

#### 三层记忆架构

```
┌─────────────────────────────────────────┐
│           工作记忆 (上下文窗口)            │
│    当前对话 + 相关 Rules + 激活的 Skill    │
└─────────────────┬───────────────────────┘
                  │ 压缩/外化
                  ▼
┌─────────────────────────────────────────┐
│           短期记忆 (Session)             │
│    .tasks/{task-id}/state.md            │
│    任务状态、决策、进度                   │
└─────────────────┬───────────────────────┘
                  │ 归档/总结
                  ▼
┌─────────────────────────────────────────┐
│           长期记忆 (Cross-Session)        │
│    ~/.claude/memory/                    │
│    - MEMORY.md (索引)                    │
│    - user_profile.md (开发者画像)         │
│    - projects/ (项目记忆)                │
└─────────────────────────────────────────┘
```

#### 记忆更新策略

| 类型 | 更新时机 | 保存内容 | 格式 |
|------|---------|---------|------|
| **User** | 了解新信息时 | 角色、偏好、技能 | Markdown + Frontmatter |
| **Feedback** | 用户纠正/确认时 | 行为规则、偏好 | Markdown + Why/How |
| **Project** | 项目里程碑时 | 决策、架构、ADR | Markdown |
| **Reference** | 发现外部资源时 | 链接、用途 | Markdown 列表 |

### 4. Hooks（角色脚本层）

基于角色的自动化检查脚本。

#### Hook 类型

| Hook | 角色 | 触发时机 | 功能 |
|------|------|---------|------|
| **ace.java-compile-check.sh** | backend, fullstack | 修改 .java 文件后 | 自动编译检查 |
| **ace.ts-type-check.sh** | frontend, fullstack | 修改 .ts/.tsx 后 | TypeScript 类型检查 |
| **ace.kt-compile-check.sh** | client, fullstack | 修改 .kt 文件后 | Kotlin 编译检查 |

#### Hook 执行流程

```
用户执行操作
    ↓
Hookify 拦截
    ↓
检查是否有相关 Hook
    ↓
执行 Hook 脚本
    ↓
成功 → 继续操作
失败 → 阻止操作 + 显示错误
```

---

### 5. Hookify（安全守卫层）

运行时安全保护，拦截危险操作。

#### 三层防护

```
┌─────────────────────────────────────────┐
│           第一层：命令拦截                │
│    拦截 rm -rf、git push --force 等       │
│    触发方式：正则匹配 + 语义分析          │
└─────────────────────────────────────────┘
                  │
                  ▼ 通过
┌─────────────────────────────────────────┐
│           第二层：文件保护                │
│    检测 .env、密钥文件编辑               │
│    触发方式：文件路径匹配 + 内容检测      │
└─────────────────────────────────────────┘
                  │
                  ▼ 通过
┌─────────────────────────────────────────┐
│           第三层：验证要求                │
│    提交前要求编译/测试通过               │
│    触发方式：Git 钩子 + 命令拦截          │
└─────────────────────────────────────────┘
```

#### 守卫配置

```yaml
# ~/.hookify/config.yaml
guards:
  block-dangerous-ops:
    enabled: true
    blocked_commands:
      - "rm -rf /"
      - "git push --force"
      - "DROP TABLE"
    
  protect-secrets:
    enabled: true
    protected_patterns:
      - "*.env"
      - "*secret*"
      - "*private-key*"
    
  require-verification:
    enabled: true
    pre_commit_checks:
      - compile
      - test
```

## 交互流程

### 典型开发会话

```
1. 开发者启动 Claude Code
   └── 加载 ~/.claude/CLAUDE.md
       └── 解析 @ 引用，加载 8 条 Rules

2. 开发者输入请求
   └── "帮我实现用户登录功能"

3. Skill 匹配
   └── coding skill 触发（关键词：实现）
       └── 加载 SKILL.md
           └── 意图路由 → 实现意图
               └── 加载 references/implement-guide.md

4. 规则应用
   └── thinking 规则 → 分析需求
   └── clean-code 规则 → 约束代码质量
   └── code-quality 规则 → 编辑时加载

5. 执行过程
   └── Plan Mode 激活
       ├── 探索代码结构
       ├── 规划实现方案
       └── 用户确认
   └── 执行代码生成
       ├── 编译检查（Hook）
       ├── 代码生成
       └── 验证（测试）

6. 记忆更新
   └── 重要决策 → 写入 .tasks/state.md
   └── 项目知识 → 更新 MEMORY.md
```

## 扩展点

ACE 设计了多个扩展点，支持自定义：

### 1. 自定义 Rules

```bash
mkdir -p ~/.claude/rules/custom
echo "# 我的团队规则" > ~/.claude/rules/custom/team-style.md
```

在 `~/.claude/CLAUDE.md` 中添加：
```markdown
## 团队规则
- @~/.claude/rules/custom/team-style.md
```

### 2. 自定义 Skills

```bash
mkdir -p ~/.claude/skills/custom/my-skill
echo "# My Skill" > ~/.claude/skills/custom/my-skill/SKILL.md
```

### 3. 自定义 Hooks

```bash
# 添加新的 Hook
echo '#!/bin/bash
npm run lint' > ~/.hookify/hooks/ace.lint-check.sh
chmod +x ~/.hookify/hooks/ace.lint-check.sh
```

### 4. 自定义 Memory 模板

```bash
# 修改角色模板
cp templates/memory/roles/backend.md ~/.claude/memory/my-profile.md
# 编辑后，在 ace init 时指定
```

## 设计原则

ACE 架构遵循以下核心原则：

### 1. 渐进式增强

```
Core → Rules → Skills → Hooks → Memory → Spec
     ↑
   每一层都是可选的，按需启用
```

### 2. 非侵入式

- 命名空间隔离：`ace/` 前缀
- 智能合并：不覆盖现有配置
- 可逆操作：`ace uninstall` 恢复

### 3. 认知负荷优化

- 信息分层：只在需要时加载
- 渐进披露：从核心到细节
- 模式识别：常见任务快速路径

### 4. 反馈闭环

```
执行 → 验证 → 反馈 → 调整
              ↓
        持续改进
```
