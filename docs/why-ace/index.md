# 为什么选 ACE？

ACE 不是又一个配置工具，而是基于认知科学和软件工程最佳实践的**AI 开发环境**

---

## 一句话定位

> ACE = Claude Code 官方最佳实践 × 认知科学 × 软件工程 × 一键部署

---

## 核心价值主张

### 🧠 认知增强

Claude Code 本身很强大，但**默认配置**是通用型的。ACE 通过 8 条认知规则和 4 个专业 Skills，将 Claude 调校为**专业级开发伙伴**。

| 问题 | ACE 的解决 |
|------|-----------|
| Claude 思考深度不够？ | `thinking` 规则强制六字原则 |
| 代码质量参差不齐？ | `clean-code` + `code-quality` 规则 |
| 复杂任务容易迷失？ | `auto-goal` skill 的 OODA 循环 |
| 开发流程不规范？ | `coding` skill 的三层架构 |

### 🛡️ 安全防护

```
用户: 删除整个数据库
Claude: 等等，这是危险操作...

Hookify 守卫拦截 → 要求确认 → 防止事故
```

3 层防护体系：
- **Hookify** — 运行时危险操作拦截
- **Hooks** — 编译/类型检查前置
- **Rules** — 代码质量内建

### 🎯 角色定制

不同技术栈，不同最佳实践：

```bash
# 后端开发者获得
✓ Java 编译检查 Hook
✓ Spring Boot 最佳实践记忆

# 前端开发者获得
✓ TypeScript 类型检查 Hook
✓ React/Vue 组件规范记忆

# 全栈开发者获得
✓ 双重检查 + 全栈思维模式
```

### 📝 规范驱动

ACE 集成 OpenSpec，实现**需求-设计-代码**的可追溯：

```
需求文档 → 设计决策 → 代码实现 → 变更历史
     ↑                                ↓
     └────────  可追溯  ←─────────────┘
```

## 适合谁？

### 👨‍💻 个人开发者

**场景**：想让 Claude Code 成为真正的开发伙伴

**ACE 提供**：
- 专业级代码质量保障
- 复杂任务自主完成能力
- 个人编码习惯的记忆

### 👥 技术团队

**场景**：团队统一 AI 辅助开发标准

**ACE 提供**：
- 统一的代码规范
- 安全防护防止误操作
- 规范驱动的需求管理

### 🏢 企业开发

**场景**：大规模采用 AI 辅助开发

**ACE 提供**：
- 可审计的决策记录 (OpenSpec)
- 符合企业安全要求
- 可定制的规则体系

---

## 不适用场景

ACE **不是**为以下场景设计的：

| 场景 | 原因 | 替代方案 |
|------|------|---------|
| 简单脚本编写 | 过重 | 直接用 Claude Code |
| 非代码任务 | 不相关 | 默认 Claude Code |
| 已有完善配置 | 可能冲突 | 手动选择性迁移 |
| 一次性使用 | 无价值 | 临时配置 |
