# 哲学基础

探索 ACE 的哲学根基：实用主义、现象学、知识论

---

## 1. 实用主义 (Pragmatism)

### 1.1 John Dewey 的反思性思维

**Dewey** 将反思性思维定义为：

> "对信念或知识形式进行主动、持续、审慎的考查。"

### 1.2 探究过程

反思性思维的探究过程：

```
感知困惑 → 定义问题 → 分析问题 → 提出假设 → 验证假设
```

**关键洞察**：这不是线性流程——问题解决者在各阶段间反复穿梭。

### 1.3 Pierce 的溯因推理

**Charles Sanders Peirce** 提出溯因推理 (Abduction)：

> "面对意外观察，应生成'最佳解释假设'，然后验证。"

| 推理类型 | 方向 | 说明 |
|---------|------|------|
| 演绎 | 一般 → 特殊 | 必然性结论 |
| 归纳 | 特殊 → 一般 | 概率性结论 |
| 溯因 | 结果 → 最佳解释 | 发现性推理 |

### 1.4 ACE 应用

#### 问题定义优先

ACE 强调：

```
遇到任务 → 最重要的不是立即规划
              ↓
           而是准确定义
              ↓
      "要解决的真正问题是什么"
```

许多失败源于解决了**错误的问题**。

#### 假设-验证循环

ACE 的每个行动都应视为假设验证：

```
"我认为这个文件包含配置信息" → 假设
读取文件 → 验证
```

#### 非线性探究

ACE 允许在以下阶段灵活跳转：

```
理解问题 ←→ 规划方案 ←→ 执行 ←→ 验证
```

而非强制线性执行。

## 2. 现象学 (Phenomenology)

### 2.1 Heidegger 的上手与在手

**Martin Heidegger** 区分了两种与工具的关系：

| 上手 (Ready-to-hand) | 在手 (Present-at-hand) |
|---------------------|----------------------|
| 工具透明地融入活动 | 工具"显现"为审视对象 |
| 注意力在任务 | 注意力在工具本身 |
| 熟练使用锤子时，意识中只有钉子 | 锤子故障时，开始审视锤子 |

**Breakdown** (故障/断裂) 触发从上手到在手的转变。

### 2.2 ACE 应用

#### 透明工具使用 vs 显式工具审查

**正常流程**（上手模式）：

```
流畅地使用工具
文件读写、命令执行
不需要过度反思工具本身
```

**工具失败时**（在手模式）：

```
切换到"在手"模式
停下来审视：
- 工具使用方式正确？
- 参数是否正确？
- 是否应该换一个工具？
```

#### Breakdown 是认知升级的契机

ACE 的 Reflect-then-Retry：

```
故障 → 暴露心智模型与现实的差距
         ↓
    宝贵的学习信号
         ↓
    每次 breakdown 都应触发反思：
    "为什么我的预期与现实不符？"
```

## 3. 知识论 (Epistemology)

### 3.1 确定性的层级

传统知识论 (JTB: Justified True Belief) 要求知识是"被证成的真信念"。

但在实践中，我们的认知确定性存在层级：

```
事实 (Fact) > 推断 (Inference) > 假设 (Hypothesis) > 猜测 (Guess)
```

| 层级 | 特征 | 行动策略 |
|------|------|---------|
| **事实** | 直接观察到 | 可基于此决策 |
| **推断** | 从事实合理推导 | 高置信度决策 |
| **假设** | 有理由的猜测 | 低风险探索 |
| **猜测** | 无依据的推测 | 需尽快验证 |

### 3.2 ACE 应用

#### 信息标记分级

ACE 要求明确标记确定性级别：

```markdown
- **FACT** — 经过验证（工具输出、测试结果、文档确认）
- **INFER** — 基于事实的推断（标注依据 + 置信度高/中/低）
- **ASSUME** — 未经验证的假设（标注验证方法 + 置信度高/中/低）
```

#### 确定性-风险匹配

```
不可逆操作 → 基于事实
低风险探索 → 可以基于假设
```

确定性级别与行动代价应匹配。

## 4. 维特根斯坦的语言游戏

### 4.1 意义即使用

**Ludwig Wittgenstein** 提出：

> "词语的意义不在于定义，而在于使用。"

过度具体的规则在新语境中失效，而抽象原则可以被重新诠释以适应新情境。

### 4.2 ACE 应用

#### 传意不传形

ACE 的 skill-optimize 原则：

```
变换前："ALWAYS 用 bullet 列表"
变换后："用 bullet 列表因为它们易于扫描——
         但当顺序重要时改用有序列表"
```

传递的是*意图*（为什么），而非*形式*（做什么）。

#### 原则 vs 规则

```
规则：在所有情况下做 X
原则：因为 Y 原因，在 Z 情境下做 X 是好的

原则更灵活，可适应新情境
```

## 5. 波兰尼的默会知识

### 5.1 Tacit Knowledge

**Michael Polanyi** 指出：

> "我们知道的比能说出来的多。"

最高效的知识传递不是列规则，而是**展示专家面对歧义时的判断过程**。

### 5.2 ACE 应用

#### Skill 的成熟度光谱

```
Level 0: 操作手册 — "先做A，再做B"
Level 1: 决策树   — "在X情况下选择Y，因为Z"
Level 2: 原则框架 — "遵循这些原则，在具体情境中自主判断"
Level 3: 认知协议 — "像这个领域的专家一样思考"
```

ACE 追求 Level 2-3，因为原则和思维方式很少过时。

#### 展示判断过程

ACE 的决策文件记录：

```markdown
## Decisions

- {决策}: {理由} (备选: {被否方案})
```

展示为什么这样选择，而非仅展示结果。

## 6. 奥卡姆剃刀

### 6.1 如无必要，勿增实体

**William of Ockham** 的奥卡姆剃刀：

> "Entities should not be multiplied without necessity."

### 6.2 ACE 应用

#### 信噪比优化

ACE 的 skill-optimize 原则：

```
每句话都必须证明自己存在的必要性

删掉一句话，如果行为不变，它就是噪声
```

#### 简洁性优先

```
5 条精确的规则胜过 20 条模糊的规则
```

## 总结

哲学为 ACE 提供了以下核心洞察：

| 哲学流派 | 核心洞察 | ACE 实践 |
|---------|---------|---------|
| 实用主义 | 反思性思维、溯因推理 | 问题定义优先、假设-验证循环 |
| 现象学 | 上手/在手、Breakdown | 工具透明使用、故障即学习 |
| 知识论 | 确定性层级 | 信息标记分级、风险匹配 |
| 语言哲学 | 意义即使用 | 传意不传形、原则优于规则 |
| 认识论 | 默会知识 | Skill 成熟度、展示判断过程 |
| 奥卡姆剃刀 | 如无必要勿增实体 | 信噪比优化、简洁性优先 |
