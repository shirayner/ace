# llm-wiki-generator 流程自动化优化

> 取消所有用户确认节点，改为意图识别驱动：从用户消息提取意图，按意图选择全自动/指定范围/手动配置三条路径。

## 意图识别模型

用户消息 → LLM 提取意图信号：

| 意图信号 | 关键词/模式 | 路径 |
|---------|-----------|------|
| 手动配置 | "手动"、"自己编辑"、"我来配" | 写 _meta.yml 骨架 → 停止 |
| 指定范围 | "扫描 X 包"、"所有 @Consumer"、"src/pages 下"等 | 自然语言解析 → 扫描 → 摘要 → 构建 |
| 默认 | "生成 Wiki"、"构建知识库"、被其他 Skill 调用 | 自动扫描 → 摘要 → 构建 |
| 直接构建 | "开始构建"、_meta.yml 已有 anchors | 解析 anchors → 摘要 → 构建 |

## 优化后流程

```
用户触发 Skill
  ↓
Step 0: 意图识别（LLM 解析用户消息）
  ↓
  ├─ "手动配置" → _meta.yml 不存在? 创建骨架 : 提示已有
  │     输出提示 → 停止
  │
  ├─ "指定范围" → 自然语言解析 → 追加到 _meta.yml
  │     → 自动扫描 → 展示摘要 → 直接进入构建
  │
  └─ "默认/直接构建" → 检查 _meta.yml
        ├─ 不存在 → 创建骨架 → 自动扫描 → 写入 → 摘要 → 构建
        ├─ anchors 为空 → 自动扫描 → 写入 → 摘要 → 构建
        └─ anchors 不为空 → 解析 → 摘要 → 构建

构建阶段:
  Phase 1: 锚点发现（规则解析 + 去重）
  Phase 2: 并行生成锚点 Wiki（8 并发）
  Phase 3: 并行生成 INDEX + SUMMARY
  Phase 4: 校验与报告
```

## 移除的确认点

| 原确认点 | 优化后 |
|---------|--------|
| 分支 A 初始化 3 选 1 菜单 | 意图识别替代 |
| 自然语言每轮"确认?" | 直接写入 |
| 自然语言"继续追加或回复开始构建" | 直接构建 |
| 自动扫描"确认无误后回复开始构建" | 摘要 → 直接构建 |
| Phase 1 "共 N 个锚点，开始构建?" | 摘要 → 直接构建 |

## 新增：摘要输出格式

构建前输出一行摘要：

```
扫描到 14 个锚点 (api:12 mq:1 job:1)，开始生成 Wiki...
```

## 保留不变

- 构建流水线 4 阶段（Phase 1-4）
- 模板文件结构和格式
- 自然语言解析规则
- 自动扫描规则
- 校验规则
- 失败不阻塞策略
