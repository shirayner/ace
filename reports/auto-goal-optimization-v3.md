# Auto-Goal 极简优化方案（v3）

> 分析日期: 2026-04-22
> 分析主题: 基于"信任模型原生能力、只做模型不会自发做的事"原则的精简方案
> 前序: v2 报告识别了 18 项优化方向，但整体方案仍然过重。本版本彻底收敛
> 设计约束: 模型能力会持续增强，skill 应随模型变强而越来越轻

---

## 1. 精简哲学：Skill 只做模型不会自发做的事

### 1.1 核心论证

一条思考链：

1. Claude Opus 已经是极强的推理引擎——它天生会分析、规划、验证、从错误中学习
2. 当前 SKILL.md 296 行中，大部分是在**教模型它已经会的事**（如何推理、如何验证、如何分解问题）
3. 这些指令消耗 ~5000 tokens 的上下文空间，但模型**即使没有这些指令也会做类似的事**
4. 更糟糕的是：过度指导可能**干扰**模型的原生推理——用固定流程替代了灵活的适应性思考
5. 随着模型持续增强，这种"教会的东西"越来越多，指令的 ROI 持续下降
6. **因此**：skill 应该只做模型**不会自发做的事**，其余全部信任模型

### 1.2 模型不会自发做的三件事

经过 v2 分析和对 Claude Code 行为模式的观察，模型有三个**结构性盲区**——不是能力不足，而是**默认行为模式**不匹配：

| 盲区 | 为什么是结构性的 | 必须显式指导 |
|------|----------------|-------------|
| **不会主动停下来问用户** | 模型的训练目标是"生成有帮助的回复"，不是"在不确定时暂停"。默认行为是用自己的推断填补空白，而非暴露不确定性 | **对齐机制**：首轮对齐 + 方向性决策时暂停 |
| **不会主动外化状态到文件** | 模型在上下文内思考，不会自发创建持久化的状态文件。跨会话协调需要显式的文件协议 | **状态协议**：.tasks/ 文件结构 + 恢复流程 |
| **不会主动管理自己的上下文** | 模型不感知上下文压力，不会主动使用 sub-agent 隔离探索或压缩已完成阶段 | **上下文纪律**：隔离/压缩/外化的触发条件 |

### 1.3 精简公式

```
新 SKILL = 3 个硬规则（不可删除）
         + 少量生成式原则（引导方向，不规定过程）
         + 1 个文件协议（跨会话协调）
         + 信任模型处理其余一切
```

**目标**：从 296 行 → ~80-100 行。不是"压缩"（同样的内容用更少的字说），而是**删除**（模型已经会的就不说）。

### 1.4 未来兼容性

这个设计天然兼容模型能力增强：
- 模型变强 → 更多行为变成"原生能力" → skill 可以进一步精简
- 极限情况：模型足够强时，skill 只剩 3 个硬规则 + 文件协议
- 生成式原则不需要随模型增强而修改，因为它们指定的是**方向**而非**过程**

## 2. 分诊：296 行逐块审计

### 2.1 审计标准

对当前 SKILL.md 的每个模块，问三个问题：

1. **没有这段指令，模型会犯什么具体错误？**（能描述具体场景 → 保留）
2. **模型的原生行为已经覆盖了吗？**（Opus 级模型自然会做 → 删除）
3. **能用一句生成式原则替代吗？**（一句话能推导出同样行为 → 替代）

### 2.2 逐块审计结果

| 模块 | 当前行数 | 判定 | 理由 |
|------|---------|------|------|
| **核心信念** | ~3 行 | ✅ 保留（精简） | "对齐优先于效率"是最核心的行为锚点，模型不会自发产生这个优先级 |
| **六字原则** | ~10 行 | ✅ 保留 | 紧凑的生成式原则集，ROI 极高。6 条原则覆盖了大量具体行为 |
| **域感知路由表** | ~12 行 | ❌ 删除 | Opus 天然会评估问题复杂度并选择匹配策略。Cynefin 四域分类是学术框架，模型不需要这个标签系统就能做出正确判断 |
| **对齐评估** | ~20 行 | ⚡ 替代 | EXPLICIT/ALIGNED/GUESSING 三级有价值，但 5 条信号 + 铁律 可压缩为一条原则："在替用户做选择时，必须暂停确认" |
| **首轮对齐** | ~25 行 | ✅ 保留（精简） | **硬规则，不可删除**。但三步流程描述可以大幅精简——模型知道怎么呈现理解，只需要告诉它"必须做" |
| **OODA 循环图** | ~15 行 | ❌ 删除 | 模型天然在循环中工作（感知→思考→行动→观察）。画一个框图不会让它做得更好 |
| **对齐门控** | ~5 行 | ⚡ 合并 | 三个问题的本质就是"我在替用户做选择吗？"——合并到对齐原则中 |
| **弱信号检测** | ~4 行 | ❌ 删除 | 模型原生具备——当它注意到进展减速或异常时自然会调整。写出来是在教它已经会的事 |
| **假设驱动行动** | ~5 行 | ❌ 删除 | 好的推理模型本身就是假设驱动的。这段是在描述模型已有的推理模式 |
| **推理模式选择** | ~3 行 | ❌ 删除 | "不可逆选择→生成备选评估"——这就是模型的默认行为。删除不会导致任何行为退化 |
| **验证精度分级** | ~3 行 | ⚡ 替代 | 替代为一句话："验证力度匹配错误成本" |
| **深度调节** | ~3 行 | ❌ 删除 | 模型自然根据复杂度调节思考深度。数字标签（1-4）增加认知负荷，不增加行为质量 |
| **熔断器** | ~3 行 | ⚡ 替代 | 替代为一句话："卡住时换方向，不换力度" |
| **偏差累积检测** | ~4 行 | ⚡ 合并 | 合并到对齐原则——假设累积的本质就是在替用户做选择 |
| **终态证伪** | ~2 行 | ✅ 保留 | 一句话，极高 ROI。模型默认会问"能不能运行"，但不会默认问"什么条件下会失败" |
| **澄清机制** | ~30 行 | ⚡ 大幅精简 | Must-Ask 5 条 + Should-Ask 3 条 + 汇入信号 4 条 = 12 条规则。实质可压缩为一条原则 + 一个示例 |
| **策略工具箱** | ~20 行 | ⚡ 大幅精简 | 四个策略名（探索/规划/执行/试探）有价值作为词汇表。但每个策略的详细描述是在教模型如何探索、如何规划——它已经会了 |
| **上下文工程** | ~15 行 | ✅ 保留（精简） | 模型**不会自发管理上下文**——这是结构性盲区之一。但 4 行表格 + 压缩保护列表可以更紧凑 |
| **信息分级** | ~8 行 | ❌ 删除 | FACT/INFER/ASSUME 是好框架，但 Opus 原生就会区分确定性层级。写出来是冗余的 |
| **意图置信度** | ~6 行 | ⚡ 合并 | GUESSING 时必须问——合并到对齐原则 |
| **Reflect-then-Retry** | ~15 行 | ❌ 删除 | 7 步反思流程是在教模型如何反思。Opus 遇到失败时自然会诊断原因、调整策略。写出来不会让它做得更好 |
| **优雅降级** | ~8 行 | ⚡ 替代 | 替代为一句话："永不空手而归——任意时刻中断都应有可用产出" |
| **记忆架构** | ~25 行 | ✅ 保留（精简） | **文件协议不可删除**——模型不会自发创建这个结构。但 state.md 的 8 条结构指引可精简 |
| **恢复验证** | ~4 行 | ✅ 保留 | 跨会话恢复需要显式协议 |
| **介入模式** | ~25 行 | ⚡ 大幅精简 | 两种模式 + 对比表 + 底线表 → 可压缩为几行。模型理解"协作 vs 自动"不需要详细对比表 |
| **用户视角模拟** | ~3 行 | ❌ 删除 | 好的提醒，但模型原生 Theory of Mind 能力已覆盖。对齐原则已经蕴含了这层意思 |
| **反模式表** | ~12 行 | ❌ 删除 | 8 个反模式 + 8 个解药 = 16 条知识。模型已经知道这些反模式。写出来是百科全书式的冗余 |

### 2.3 审计汇总

| 判定 | 行数（估算） | 占比 |
|------|-------------|------|
| ✅ 保留（精简后） | ~50 行 | 17% |
| ⚡ 替代为生成式原则 | ~70 行 → ~15 行 | 24% → 5% |
| ❌ 删除（模型原生覆盖） | ~176 行 | 59% |

**结论**：当前 SKILL.md 约 59% 的内容是在教模型它已经会的事。精简后预计 ~70-80 行。

## 3. 精简后设计：新版 SKILL.md 草案

以下是完整的新版 SKILL.md 草案。~85 行，替代当前 296 行。

### 📄 新版 SKILL.md 全文

```markdown
# Auto Goal Skill

自主完成目标的赋能系统。信任模型的推理能力，只做模型不会自发做的事。

**核心信念**：对齐优先于效率。准确完成用户真正想要的，胜过高效完成 agent 以为的。

## 思考罗盘（始终生效）

| 字 | 含义 | 自检 |
|----|------|------|
| **序** | 理解先于行动 | 理解够启动下一步吗？ |
| **验** | 事实闭环，证伪导向 | 什么条件下结论不成立？ |
| **深** | 多问一层为什么 | 到根因层了吗？ |
| **广** | 系统中定位局部 | 改动影响传向何方？ |
| **辨** | 区分事实/推断/假设 | 确定性够支撑决策吗？ |
| **简** | 复杂度需要理由 | 能更简单吗？ |

---

## 三条硬规则（不可跳过）

### 规则 1：首轮对齐（MANDATORY）

接收目标后，**必须先向用户呈现理解，等待确认后再执行**。

呈现内容：
1. 我的理解 — 一两句话复述目标核心意图
2. 计划方向 — 打算怎么做（高层策略）
3. 关键假设 — 如果有不确定的假设，标注出来

有歧义时先用 AskUserQuestion 澄清，再呈现对齐。用户确认后进入执行。

### 规则 2：替用户做选择时，必须暂停

模型最危险的特征是自信地做错事。以下情况**必须暂停，向用户呈现选项**：
- 存在多个可行方案且各有取舍
- 决策依赖用户偏好（风格、架构、优先级）
- 范围超出原始目标描述
- 不可逆操作（删除、重写、架构变更）
- 正在用自己的理解填补用户未说明的部分

**一句话判断**：如果用户此刻看到我的决策会惊讶 → 暂停询问。

### 规则 3：长任务外化状态

预估超过 10 步的任务，必须创建状态文件：

```
.tasks/auto-goal-{id}/
├── state.md          # 目标 + 进度 + 下一步 + 关键假设
├── decisions.md      # 关键决策 + 理由（按需创建）
└── reflections.md    # 失败分析 + 经验（按需创建）
```

**state.md 必备项**：目标（含验收标准）、当前进度、下一步行动、已修改文件列表。
**为陌生读者而写**：让一个全新 agent 能读懂并继续。

---

## 生成式原则（引导方向，不规定过程）

以下原则指定**方向**，模型自主决定**如何**执行：

1. **验证 ∝ 风险** — 验证力度匹配错误成本。改个注释不需要跑全量测试，改认证逻辑需要深度验证
2. **卡住时换方向** — 同一方法连续失败时换策略，不加力度。三次失败后质疑前提
3. **永不空手而归** — 任意时刻中断都应有可用产出。按价值排序交付
4. **上下文是稀缺资源** — 探索性工作用 sub-agent 隔离；大阶段完成后压缩保留决策和结论；关键中间结果外化到文件

---

## 上下文纪律

| 策略 | 时机 |
|------|------|
| **隔离** — 搜索/读大文件/查资料用 sub-agent | 会污染主上下文的工作 |
| **压缩** — 已完成阶段只保留决策和结论 | 大阶段完成后 |
| **外化** — 关键发现/决策写入状态文件 | 重要信息出现时 |

压缩时必须保留：当前目标、关键决策及理由、已修改文件、未完成待办。

---

## 恢复协议

恢复中断的任务时：
1. 读取 `.tasks/auto-goal-{id}/state.md`
2. 验证声称的产出是否真实存在（Glob/Read 轻量确认）
3. 用 TaskCreate 重建 UI 进度
4. 从"下一步行动"继续

---

## 介入模式

- **协作**（默认）：自主执行，方向性决策前确认
- **全自动**：仅不可逆操作前确认

未声明时默认协作。
```

| 维度 | 当前版本 | 新版本 | 变化 |
|------|---------|--------|------|

| **Token 消耗** | ~5000 tok | ~1500 tok | -70% |

### 3.2 删除的不是价值，是冗余

需要强调：被删除的内容（OODA 详细步骤、Reflect-then-Retry、域感知路由、反模式表等）不是"不好的设计"。它们在设计时是正确的思考。但在 Opus 级模型上，这些指令的**边际价值接近零**——模型即使没有这些指令也会做类似的事。

删除它们释放了 ~3500 tokens 的上下文空间，减少了注意力稀释，让模型有更多空间发挥原生推理能力。

### 3.3 三条硬规则为什么不能删

| 硬规则 | 删除后的具体故障场景 |
|--------|---------------------|
| 首轮对齐 | 模型会直接开始执行。用户说"优化性能"，模型可能花 20 分钟优化了错误的维度。没有首轮对齐，这种偏差在交付时才暴露 |
| 替用户做选择时暂停 | 模型遇到分叉会用自己的"最佳判断"选一条路。但用户的偏好不在模型的训练数据中。10 次中有 3-4 次会选错方向 |
| 长任务外化状态 | 会话中断后（上下文溢出/用户关闭/网络断开），所有进度丢失。下次会话从零开始。用户的 30 分钟工作白费 |

## 4. 风险评估与兜底策略

### 4.1 精简的已知风险

| 风险 | 严重度 | 概率 | 兜底 |
|------|--------|------|------|
| **模型在某些场景下不够强** — 弱于 Opus 的模型可能真的需要那些被删除的指令 | 中 | 低（目标场景是 Opus+） | 生成式原则设计为"越强的模型执行得越好，但弱模型也不会完全失效"。如果需要支持弱模型，可以恢复部分删除内容作为扩展层 |
| **模型不遵守硬规则** — 在某些情况下模型可能跳过首轮对齐 | 高 | 低 | 硬规则用 **MANDATORY** + 粗体 + 独立章节强调。如果仍然跳过，是模型的基础指令遵从问题，加更多规则也解决不了 |
| **生成式原则太抽象** — 模型可能不知道如何"展开"原则为具体行为 | 中 | 低 | 每条原则都附带了具体场景提示（如"改个注释不需要跑全量测试"）。如果仍然太抽象，可以增加 1-2 个 worked example |
| **删除反模式表后模型陷入反模式** — 如确认偏误、盲目重试 | 中 | 极低 | Opus 级模型的元认知能力已经覆盖这些反模式。"卡住时换方向"这一条原则实际上生成了大部分反模式的解药 |

### 4.2 渐进式精简策略

不需要一步到位。推荐的实施路径：

```
Phase 1: 删除明确冗余（~100 行）
  - 删除：域感知路由详细表、OODA 循环图、反模式表、Reflect-then-Retry 详细步骤
  - 删除：推理模式选择、深度调节、弱信号检测、假设驱动行动
  - 风险：极低。这些是模型原生能力

Phase 2: 替代为生成式原则（~70 行 → ~15 行）
  - 合并：对齐评估 + 对齐门控 + 偏差检测 + 意图置信度 → "替用户做选择时暂停"
  - 替代：验证分级 → "验证 ∝ 风险"
  - 替代：熔断器 + 降级 → "卡住换方向" + "永不空手而归"
  - 精简：澄清机制 12 条规则 → 1 条原则
  - 风险：低。观察几轮实际任务，确认行为不退化

Phase 3: 精简保留内容（~50 行 → ~35 行）
  - 精简：首轮对齐流程描述
  - 精简：上下文工程表格
  - 精简：介入模式
  - 精简：记忆架构和恢复协议
  - 风险：中。需要逐条评估，确保不丢失关键信息
```

### 4.3 评估方法

精简后需要在实际任务中验证。关键观测指标：

| 指标 | 怎么观测 | 红线 |
|------|----------|------|
| **首轮对齐执行率** | 模型是否在每次调用时都呈现理解 | 低于 95% → 强化硬规则措辞 |
| **方向偏差率** | 用户需要纠正方向的频率 | 高于当前版本 → 恢复部分对齐指令 |
| **上下文浪费** | 模型是否使用 sub-agent 隔离探索 | 不使用 → 强化上下文纪律措辞 |
| **跨会话恢复成功率** | 中断后能否正确恢复 | 低于 80% → 增强文件协议细节 |
| **任务完成质量** | 最终交付是否满足用户需求 | 低于当前版本 → 回滚并分析 |

### 4.4 设计的终极检验

对新版 SKILL.md 应用自身的"简"原则——**每一行都问：删掉它会导致什么具体错误？**

如果答案是"不确定"或"可能"——删掉它。模型比我们以为的更强。
