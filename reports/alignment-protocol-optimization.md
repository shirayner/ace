# Alignment Protocol 优化方案

## 背景

alignment-protocol.md 存在三个核心问题：
1. 深度思考流于表面——是"检查清单"而非"生成式约束"
2. 探索不充分——被动列举输入源，没有充分性判定
3. 不能反驳人类——缺少 Defeater 搜索机制

## 核心理论：认知互补模型

```
┌─────────────────────────────────────────────────────────┐
│                                                         │
│   Human 认知域          共识域          AI 认知域       │
│   (H \ A)              (H ∩ A)         (A \ H)         │
│                                                         │
│   · 真实意图            · 用户说了什么   · 代码/项目现状 │
│   · 业务上下文          · 显式约束       · 技术影响链    │
│   · 隐含优先级          · 明确需求       · 逻辑不一致    │
│   · 未说出的偏好                        · 缺失的拼图    │
│   · 认知盲区中的知识                    · 人类错误检测   │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

三步流程的认知互补映射：
- **Step 1** = AI 扩大自己的认知 + 检测人类的认知错误
- **Step 2** = 获取只有人类知道的部分（人类补集）
- **Step 3** = 输出只有 AI 发现的部分（AI 补集）→ 形成共识

## 关键设计决策

| # | 决策 | 选择 | 理由 |
|---|------|------|------|
| 1 | 架构 | 协议自包含（不依赖 CLAUDE.md） | 独立可执行 |
| 2 | 反驳强度 | 默认开启 Defeater 搜索 | 每次都搜索，攻破才输出 |
| 3 | 探索 | 问题驱动式 | goal-directed > data-driven |
| 4 | 反驳方法 | Steel-man → Attack | 防止为反驳而反驳 |
| 5 | 反驳输出 | 融入 Step 3 关键假设 | 不增加额外步骤 |
| 6 | "序"中删除 | "投入的思考量应匹配问题的复杂度" | 防止偷懒逃生舱口 |

## 变更对照

| 位置 | 原版 | 新版 | 理由 |
|------|------|------|------|
| 开篇 | "确保 AI 正确理解用户意图" | 认知互补模型 | 单向理解→双向互补 |
| Step 1 | 4行四追问 + 输入源列表 | 6字纪律 + 苏格拉底追问 + 问题驱动探索 + Defeater搜索 + 质量门槛 | 解决三大问题 |
| Step 2 | 无框架注释 | "获取人类补集" | 认知互补统一 |
| Step 3 | 无框架注释 | "输出 AI 补集，形成共识" | 认知互补统一 |
| Step 3 关键假设 | 普通列表 | 增加 ⚠️ Defeater 展示位 | 反驳自然呈现 |
| Red Flags | 11条 | 12条（+不挑战=谄媚） | 防止跳过 Defeater |

| 形式验证 | 不变量检查 | 逻辑一致性检测 |
