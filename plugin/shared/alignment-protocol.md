# 对齐协议

> **核心命题**：对齐的本质是认知互补——通过结构化的澄清与确认，让 AI 与人类的盲区互相照亮，形成超越任何一方独立认知的共识。
>
> **前置依赖**：本协议假设 `understanding-protocol.md` 已执行完毕，其产出（insights/assumptions/defeaters/unknowns/grounding）作为本协议的输入。

---

## 流程

### Step 1: 执行理解层

Read `understanding-protocol.md`，按其完整流程执行。

调用方需声明参数：
- `verify`：验证策略（none / artifact-grounding / code-impact）
- `threshold`：质量门槛覆写（可选）

→ 产出 `understanding_result`

---

### Step 2: 引导性澄清（获取人类补集）

基于 `understanding_result` 中的 unknowns 和需确认的 assumptions，设计面向用户的具体问题。

**本质**：获取**只有人类知道但没说出来的**——意图、优先级、隐含约束、业务上下文。

**设计原则**：

- 具体、可行动、关联用户业务场景
- 主动指出关联："我注意到 X 还涉及 Y——是否在范围内？"
- 暴露取舍："方案 A 更简单但有 X 风险，方案 B 更复杂但更全——优先级？"

**跳过条件**（必须**同时满足全部**）：

- 同一会话中已明确表达完整意图
- understanding_result 中无 unknowns
- 不存在"用户可能惊讶"的假设
- 延续性修复（而非新目标）

**如不确定是否需要澄清 → 澄清。** 默认执行，跳过是例外。

**Terminal state = AskUserQuestion 工具调用。** 没有调用 = 此步骤未完成。

---

### Step 3: 对齐确认（输出 AI 补集，形成共识）

**本质**：将 AI 发现了但人类可能没意识到的呈现出来——包括 Defeater 攻破的认知错误、探索中发现的关联问题、以及对目标的更深层理解。

**先**用 markdown 展示四要素（每要素标题独占一行，内容换行后写）：

```
**我的理解**
（1-2 句核心意图 + 关联问题）

**计划方向**
（1-2 句高层策略）

**关键假设**
- 假设 1
- 假设 2
- ⚠️ [Defeater 攻破时] 我注意到 [断言X] 的前提可能不成立：[原因]

**完成标准**
- 可测试条件 1
- 可测试条件 2
```

格式禁忌：标题和内容同行；把内容放入 AskUserQuestion。

**然后**在同一 response 中调用 **AskUserQuestion** 确认。

**Terminal state = AskUserQuestion 工具调用。** 写了对齐内容但没调用 = 未完成。

---

## 惊讶测试

**一句话判断**：如果用户此刻看到我的决策会惊讶 → 暂停询问。

触发条件：

- 多个可行方案且各有取舍
- 决策依赖用户偏好
- 范围超出原始目标
- 不可逆操作
- 正在填补用户未说明的部分

---

## Red Flags — 正在跳过对齐

以下想法 = 正在合理化，**立即停止当前动作**：

| 你的想法                 | 真相                                    |
| ------------------------ | --------------------------------------- |
| "这个任务很简单"         | 简单 = 隐含决策被忽略，恰恰最需要对齐   |
| "用户已经说清楚了"       | 说清楚 ≠ 你理解 100% 正确              |
| "auto mode 要求立即执行" | auto mode 不覆盖对齐门禁                |
| "先探索再对齐"           | 对齐在任何操作之前                      |
| "对齐会让用户等太久"     | 做错让用户等更久                        |
| "上一轮已经对齐过了"     | 新目标 = 新对齐                         |
| "读文件就知道怎么做"     | 读文件是探索，不是对齐                  |
| "先出初版再迭代"         | 先对齐再出初版                          |
| "这只是延续性修复"       | 延续性需同时满足全部跳过条件            |
| "我理解用户要什么"       | 理解 ≠ 验证，调用 AskUserQuestion 确认 |
| "我已经写了对齐内容"     | 写了 ≠ 调用了工具，缺工具调用无效      |
| "用户不会有错"           | 不挑战 = 放弃认知互补，等于谄媚         |

**如果正在想上述任何一条 → 回到 Step 1。**

**违反形式 = 违反精神。** 对齐的形式（AskUserQuestion 工具调用）就是对齐的实质。
