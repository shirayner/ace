# 决策日志协议

> **核心命题**：一个项目"为什么长成这样"，藏在人机交互的决策分叉点里——agent 拿不准时跟用户探讨的选择，以及用户主动拍板/否决的指令。这些决策一旦落盘累积，就成为项目级真相源：凭它能在新目录复刻出**决策一致**的项目。
>
> 决策日志记的是 **why**（为什么这么选、否决了什么），不是代码。其余实现细节 agent 自主决定，无需落盘。

---

## 文件位置（单一规则）

```
现行决策 → $ROOT/.ace/project/decisions.md          （只含 accepted，复刻只读这份）
被取代的 → $ROOT/.ace/project/decisions-archive.md   （superseded 历史，按需查）
```

- 属**项目**，不属单次任务。无论哪个 changeName、哪个 skill 触发，写入同一文件。
- **懒创建**：首次出现合格决策时创建 `decisions.md`（含标题头 + TOC）；`decisions-archive.md` 首次发生 supersede 时才创建。
- 与 `.ace/experience.md` 并列：experience = 可复用经验(E{N})，decisions = 项目决策(D{N})，两者互不混写。

**为什么分两文件**：superseded 决策对复刻是纯噪声（agent 读它只为跳过它）。移出主文件后，复刻读 `decisions.md` 天然只有现行决策——零噪声、context 最省。历史仍在 archive 可追溯。

---

## 准入判据（核心铁律）

> **一个决策进 decisions.md，当且仅当——换一个选择，复刻出来的项目会不同。**

拿这条铁律刷两类来源：

**该进** ✅
- 存储/框架/协议等技术选型（换一个，项目就是另一个）
- 架构/模块划分/边界的取舍
- 产品形态、范围、非目标的拍板
- 关键行为规则（换一个，功能表现不同）

**不该进** ❌（四类噪声）
- **澄清型**："你说的 X 指 A 还是 B？" → 是理解，不是决策
- **过程型**："先跑测试吗？""用哪个分支？" → 影响流程，不影响项目形态
- **交付格式**："要 markdown 还是表格？" → 一次性
- **跨领域岔题**：在本项目里顺手问的、与本项目形态无关的问题 → 不属本项目决策

**拿不准时：默认收**（写入档案）。理由：漏一条关键决策的代价（复刻错）> 多留一条的代价（读时略过）；用户审查时删比补省力。

---

## 捕获时机（实时，不等归档）

两个触发点，命中即**立即** append（当轮 response 内完成，不拖到任务结束）：

1. **AskUserQuestion 用户回复后** — agent 探讨型决策。用户选定的选项 = 决策，未选的其他选项 = 否决项。先过准入判据（澄清/过程/格式类问答不进）。
2. **用户对话中主动拍板/否决时** — 用户主动决策。如"不用 Redis，SQLite 就够"、"改用 8001 端口"、"范围只做 X 不做 Y"。识别到即过判据、即落盘。

> ⚠️ 不等归档的原因：用户主动指正发生在任意轮次；对话中断时已落盘的决策不丢失（永不空手而归）。

---

## 文件结构与条目模板

`decisions.md` 由**顶部 TOC** + **决策条目**两部分组成。极简字段——只保留驱动"复刻"和"审查"的必要信息，不记对复刻零贡献的元数据。

```markdown
# 项目决策日志

<!-- TOC：每新增/取代一条决策后同步更新 -->
- D0001 存储选型：SQLite
- D0002 复刻语义：决策一致
- ...

---

## D{N} — {决策标题：一句话概括拍板了什么}
- {YYYY-MM-DD} · accepted
- 决策: {选定了什么}
- 否决: {否决了哪些备选 + 一句理由；无则省略此行}
```

**字段说明（只有 5 项，其余一律不记）**：
| 字段 | 作用 | 为何必要 |
|------|------|---------|
| 标题 | TOC 索引 + 一眼定位 | 复刻扫描、审查检索 |
| 日期 | 时间序 | 排序、审查 |
| 状态 | accepted / superseded by D{M} | 复刻过滤现行决策 |
| 决策 | 选定了什么（what） | 复刻核心 |
| 否决 | 否决项 + 理由 | 防复刻时重蹈覆辙（无则省略） |

**刻意不记**（对复刻零贡献、审查边际）：
- ~~来源（agent探讨/用户主动）~~、~~任务 changeName~~、~~tag~~、~~上下文~~
- 检索靠**顶部 TOC**（扫一行一条），不靠 tag——早期决策少时 tag 是纯负担，多时 TOC 比 tag 筛更直观且零维护

要求：
- 编号 D{N} 全项目递增，不重复、不复用（archive 里的号也占用，不回收）
- 一条只记一个决策（原子性）
- "决策/否决"具体可操作，不是泛泛感受
- 每次增删决策后**同步更新顶部 TOC**

## 演进：不可变 + supersede 移档

决策一旦写下**永不就地修改内容**。同一问题从 A 升级到 B 时：

1. **新增** D{new} 到 `decisions.md`，正文写 B，加一行 `- supersedes: D{old}`
2. **把 D{old} 整条移出** `decisions.md` → 追加到 `decisions-archive.md`，并把其状态改为 `superseded by D{new}`
3. **更新 TOC**：主文件 TOC 删掉 D{old} 行、加上 D{new} 行

结果：`decisions.md` 永远只含现行决策，不随取代次数膨胀；被取代的沉到 archive。

```markdown
# decisions.md（主文件，只有现行）
- D0009 本地存储：DuckDB          <!-- TOC 只列现行 -->
...
## D0009 — 本地存储改用 DuckDB
- 2026-08-01 · accepted
- supersedes: D0003
- 决策: DuckDB
- 否决: SQLite（聚合性能不足）

# decisions-archive.md（历史）
## D0003 — 本地存储选型
- 2026-07-28 · superseded by D0009
- 决策: SQLite
```

**为什么移档而非就地留**：就地保留会让主文件随时间无限膨胀，且复刻时 agent 要读一堆已作废决策再跳过——纯 context 浪费。移档后主文件恒等于"当前项目真相"，这正是与 ACE `task archive`（完成任务移出活跃目录）一致的哲学。

**为什么不做 rollup/压缩**：把多条决策总结成一条是有损的，会丢失用户亲手拍板的原文，违背不可变原则。体积控制只靠"移出 superseded"，不靠"压缩 accepted"。

---

## 体积伸缩（文件过大时）

主文件只含现行决策，天然受控。若现行决策本身很多：
- **TOC 是第一道伸缩**：无论多少条，顶部一行一条，扫描恒定成本
- 复刻时若仍嫌大：agent 可先只读 TOC 挑相关决策，再按 D 号读正文（TOC 提供了这种按需读取的锚点）
- **不按领域分片**：领域分类会产生"其他"和跨域归属难题（早前已定不预分类）。分层只按"现行 vs 被取代"这一条清晰边界。

---

## 告知用户（必须执行）

命中并落盘后，一行式告知：
- `📒 决策落盘：D{N} 已写入（{决策标题}）`
- supersede 时：`📒 决策更新：D{new} 取代 D{old}（{新决策标题}）`

准入判据判定为噪声、未落盘的，静默跳过，不告知。

---

## 复刻用法（decisions.md 作为真相源）

未来在新目录复刻项目时，把 `.ace/project/decisions.md`（**只需主文件，不需 archive**）提供给 agent：
1. 主文件已只含现行决策 → 直接全取，无需过滤（archive 里的 superseded 历史复刻时不读）
2. 决策多时可先读 TOC 挑相关项，再按 D 号读正文
3. 按现行决策集重建 → 得到**决策一致**的项目（所有用户拍过板的选择保留，agent 不在这些点擅自改主意）
4. 未记录的实现细节由 agent 自主决定

> **边界**：decisions.md 保证决策一致复刻（不在拍过板处翻案），不保证功能清单完整（未触发讨论的功能无痕迹）。用户可在复刻对话中主动补充遗漏的功能。
