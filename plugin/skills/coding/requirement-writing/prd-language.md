# PRD Language — PRD 表达语言定义

> 这门语言定义 PRD 用什么**节点类型**表达需求。LLM 会写 PRD，但不知道你的 PRD 说哪门语言——这里定义名词与编号，Template 定义每种节点长什么样。
>
> **稳定性**：Language 十年不变。新增章节类型改 `chapter-tree.md`，不改这里。

---

## 节点类型

| 节点 | 读作 | 承载什么 | 编号 |
|------|------|----------|------|
| **REQ** | Requirement | 一个功能需求：系统要有的一项能力 | `REQ-001` 起连续递增 |
| **BR** | Business Rule | 一条跨 ≥2 个 REQ 复用的公共业务规则 | `BR-001` 起连续递增 |
| **AC** | Acceptance Criteria | 一个验收场景，用 Given/When/Then 表达 | `AC-001` 起，REQ 内独立编号 |
| **Open Question** | 待决问题 | 未被澄清 Q&A 决策、且不阻塞主线的点 | 无需编号，列表即可 |

## 编号规范（全局统一，不各章自定）

- 编号实例用 `REQ-001` / `BR-001`；泛指占位用 `REQ-00X` / `BR-00X`。
- 同类条目**按出现顺序连续编号**，不按类型/优先级分段绑定编号。
- 交叉引用直接写编号（`遵循 BR-003`、`见 REQ-005`），引用目标必须真实存在。

## AC 语法（Given/When/Then）

一行一个场景，用表格承载：

```
| 编号 | 场景 | Given（前置条件） | When（动作 / 事件） | Then（可验证结果） |
|------|------|-------------------|---------------------|--------------------|
| AC-001 | <场景名> | <前置条件> | <用户动作 / 系统事件> | <可验证结果> |
```

- 一个 REQ 至少一组 AC；主路径 / 异常 / 边界各成一行。
- Then 必须**可验证**（能判定真假），不写"体验更好"这类不可测断言。
- 单元格内条件 / 结果多条时用 `；` 或 `<br>` 分隔，保持一行一场景。

## 优先级语义

| 值 | 含义 |
|----|------|
| **P0** | 本期 MVP 必须，缺则不可上线 |
| **P1** | 本期应做 |
| **P2** | 可延后 / 本期可砍 |

## 空值三态（禁止裸写"无"）

字段无内容时，必须落一种显式态，不留空、不写裸"无"：

| 态 | 何时用 |
|----|--------|
| `已确认无` | 明确核实过不存在 |
| `原文未提供（待确认）` | 来源没给，需回头确认 |
| `不适用（说明原因）` | 该字段对本需求不适用 |
