# 渐进加载决策规则

> 引用自 llm-wiki-reader SKILL.md。Agent 在判断 wiki 加载深度时参考此文件。

## 核心原则

1. **按需加载**: 不预加载、不缓存。每次决策是否需要下一层时重新判断
2. **wiki 优先但不强制**: wiki 是最佳路径，不可用时回退代码分析
3. **Agent 自主判断**: 以下规则是软指引，Agent 根据上下文自行调整

## SUMMARY → INDEX 决策：何时从 SUMMARY 进入 INDEX

| 信号 | 决策 |
|------|------|
| SUMMARY 快速查找已定位到候选锚点 | 跳过 INDEX，直接进入 anchor |
| SUMMARY 快速查找未命中，需要扫描完整锚点列表 | 进入 INDEX，按锚点目录匹配 |
| 方案设计需要了解全部锚点全景 | 进入 INDEX，了解锚点总数和类型分布 |
| 已熟悉项目锚点结构（非首次） | 自行判断 |

## SUMMARY → anchor 决策：读哪个 anchor、读几个

| 场景 | 读几个 anchor |
|------|------------|
| 理解单个锚点规则 | 1 个（目标 anchor） |
| 设计新接口（需理解现有契约） | 1 个主锚点 + 关联锚点 |
| 影响分析 | 从领域模型关联的所有锚点 |
| 跨锚点功能调研 | 业务流程涉及的全量锚点 |

## 交叉引用追踪规则

### 追踪信号

- 任务涉及多个锚点的联动
- 需要理解上下游数据流
- 当前 anchor 的业务规则引用了其他锚点的产出
- anchor frontmatter `related_business` 中有与任务高度相关的概念

### 停止信号

- 任务范围明确限定在单一锚点
- 已读 anchor 足够回答当前问题
- 后续 anchor 与任务关键词无交集
- token 预算紧张（>50% 已消耗）

## 异常处理

| 异常 | 决策 |
|------|------|
| wiki 不存在 | 跳过 wiki，代码分析兜底，提示用户生成 |
| 某层 wiki 定位失败 | 退回上一层，换策略重试 |
| anchor 文件缺失 | 告知用户 wiki 不完整，继续用已有内容 |
| wiki 过期 | 降低可信度权重，仍在代码中验证关键规则 |
