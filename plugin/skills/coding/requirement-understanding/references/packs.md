# 按信号加载的方法包

> 方法只用于发现高价值缺口并更新 `flow.md` 的因果决策树，不产生新模型、术语表、Canvas 或用户可见报告。只加载命中信号的检查包；发现的问题仍须通过 Frontier 四条件与低价值过滤。

## 路由表

| 问题信号 | 优先方法 | 更新位置 |
|---|---|---|
| 目标只是功能或方案描述 | 5 Whys、结果链、替代方案追问 | 根因/机会、目标结果 |
| 现状流程含糊 | 场景回放、As-Is 还原 | 核心用户/场景、成立条件 |
| 方案可能删除人工步骤 | 控制作用追问 | 成立条件、关键假设 |
| 规则存在多条件组合 | 对比追问、决策表 | 成立条件、能力与边界 |
| 术语存在歧义 | 反例、边界例子、统一口径 | 相关节点原位更新 |
| 边界可能遗漏 | “只成功一半”、异常清单 | 能力与边界、完成证据 |
| 形容词不可验证 | 基线、目标、口径、时间窗 | 目标结果、完成证据 |
| 用户表达偏好而非事实 | 真实案例与损失追问 | 根因/机会、场景或假设 |
| 材料或陈述互相冲突 | 来源对照、影响分析 | 冲突节点 |

## 检查包

### 目标溯因

适用：用户直接给出功能、页面或技术方案，目标结果不清。

- 追问该方案要消除的损失或促成的变化；
- 沿“方案 → 使用变化 → 业务结果”检查因果链；
- 提出不采用该方案时的替代路径，验证方案是否被误当目标。

停止：目标已能解释为什么需要相应能力；继续追问只会得到同义答案。

### 场景回放

适用：现状仅有抽象描述，无法判断问题发生位置。

- 选一个最近或典型实例，按触发、动作、结果回放；
- 标出参与角色、系统边界、交接点和失败点；
- 区分偶发现象与稳定规则。

停止：已足以判断目标场景和职责边界。

### 控制作用

适用：目标方案自动化、合并或删除人工步骤。

- 询问该步骤当前阻止什么错误、承担什么审批或补偿；
- 检查删除后由谁或什么机制接管控制；
- 若控制无价值，再将其排除，避免把历史流程当需求。

### 条件组合

适用：行为由角色、状态、时间、金额等多个条件共同决定。

- 选取会产生不同行为的最小条件集合；
- 用对比案例找出真正的分界条件；
- 必要时在内部使用决策表检查缺口和重叠，但不把表作为确认附件。

### 术语定界

适用：同一词可能指不同实体、范围或状态。

- 给出正例、反例和边界例；
- 对比材料中各处用法；
- 确认后直接统一相关节点措辞，不另建 glossary。

### 边界与半成功

适用：只描述成功主路径，范围或异常可能遗漏。

- 问“如果只完成一半，系统和用户分别看到什么”；
- 检查取消、超时、重复、部分成功、无权限和依赖失败；
- 只保留会改变用户行为、规则、数据、验收或重要约束的边界。

### 可验证性

适用：“快速、智能、稳定、明显提升”等词无法直接验收。

- 明确比较基线、目标方向或阈值；
- 明确统计口径、观察对象和时间窗；
- 无法量化时改为可观察、可判定的行为证据，不强造数字。

### 偏好求证

适用：用户表达“最好、通常、大家都需要”等未经验证的偏好。

- 请求一个真实案例及当前损失；
- 区分个人偏好、组织规则和用户事实；
- 仅当差异会改变共识时交给用户决策。

### 冲突裁决

适用：输入、文档、代码或用户陈述互不兼容。

- 展示冲突来源、原意和各自条件；
- 说明不同选择会改变的目标、范围、行为或验收；
- 能由版本、适用范围或可靠证据消解时执行者自行查证；
- 仍属业务取舍时进入 Frontier，请用户裁决，不按最后一句覆盖。

## 使用纪律

- 方法生成的是候选缺口，不是必问题目。
- 可查事实先查；低风险、易纠正且会在对齐卡暴露的默认不问。
- 用户暂时无法回答的关键事实记为关键未知；它不阻塞独立分支，但若会改变核心需求，则阻塞 Readiness。
- 一旦缺口不再影响五段式需求对齐卡或必要拆分，立即停止该方法。
