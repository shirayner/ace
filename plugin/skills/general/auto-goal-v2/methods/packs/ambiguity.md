# 六类歧义扫描

> 命中信号：`SUBJECT_AMBIGUOUS`、`VAGUE_TERMS_PRESENT`。
> 更新：`goal.subject`、`goal.scope`、criteria、constraints。

## 六类扫描面

歧义不是「说得不清楚」，而是**同一句话有多个都合理的解释**，且不同解释导致不同判据。逐类扫描：

| 类 | 问什么 | 典型漏洞 |
|---|---|---|
| **名词** | 这个词指哪个具体实体？有几个同名对象？ | 「用户」指注册用户还是活跃用户 |
| **动词** | 这个动作的完成边界在哪？ | 「同步」指单向还是双向、实时还是批量 |
| **数量** | 多少？上限下限？超出怎么办？ | 「大量数据」是 1 万还是 1 亿 |
| **时间** | 何时生效？多久算及时？时区？ | 「每天」指自然日还是滚动 24 小时 |
| **权限** | 谁可以做？谁能看到？ | 「管理员可导出」——哪一级管理员 |
| **状态与例外** | 异常路径怎么处理？半成功状态呢？ | 「导入失败」指整批回滚还是部分成功 |

第六类最常被跳过，也最常在执行期爆炸。**半成功状态必须显式定义**。

## 模糊谓词必须量化

以下词在**任何领域**都是缺失阈值的伪装：

```text
快 慢 大量 少量 及时 合理 实时 相关 异常 友好 稳定 高效
简洁 清晰 完善 优化 提升 足够 适当 尽快 流畅 好用 干净 专业 动人
```

两条合法出路，`gateCriterion()` 强制二选一：

1. **量化**：给出阈值/计数/时间窗。「快」→「P99 < 200ms」。
2. **降级为 `JUDGMENT`** 并指定 acceptor。「动人」无法量化，那就承认判定权在人，别假装能自己判。

不合法的第三条路：保留模糊词并让 Agent 自行解释——这会在验证期变成 Agent 用自己的标准给自己打分。

## 指称消解

`subject` 必须解析到**唯一**指称。方法：

```text
1. 列出所有可能匹配的实体
2. 若 >1，这就是一个 Frontier 问题（用户才知道指哪个）
3. 高爆炸半径动作前，枚举确切目标集（→ target-enumeration）
```

「批量改名」真正的风险不是改名，是**改错目录**。作用在错的目标上，危害通常大于动作本身。

## 现状与目标对照

歧义常来自「说的是现状还是目标」混淆。对照表迫使两者分离：

```markdown
| 维度 | 现在 | 目标 | 差量 |
|---|---|---|---|
| <维度> | <现状事实> | <期望状态> | <变化> |
```

「差量」列为空的行说明该维度不在本轮范围——应移入 `scope.out`。

## 反例迫使规则显性化

给出一个**你认为应该被拒绝**的例子，问用户对不对：

```markdown
按我的理解，<反例> 应该被排除，因为 <理由>。对吗？
```

反例比正例更有效：正例容易被含糊地认可，反例会立刻暴露理解偏差。同理，两个相似但应有不同处理的例子放在一起，能迫使隐含规则显性化。

## 输出

扫描结果直接更新：

- 名词/指称歧义 → `goal.subject`、`goal.scope`
- 数量/时间歧义 → criteria 的量化条件
- 权限歧义 → `goal.principals`、constraints
- 状态与例外 → criteria（含半成功状态）

未问的歧义**登记为假设并写 defeat 条件**，不是留空。
