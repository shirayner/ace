# 目标集枚举

> 命中信号：`HIGH_BLAST_RADIUS` —— `blast_radius` 为 `bounded_many` 或 `unbounded`。
> 更新：approval scope。

## 为什么枚举本身是批准对象

批量动作的风险不在动作，在**目标集**。「批量改名」真正的危险不是改名，是改错目录。误识别的危害通常大于动作本身，而它不会被动作本身的风险评估捕捉到。

因此高爆炸半径动作的批准对象不是「你可以改名」，而是**「你可以对这 N 个具体对象改名」**。

## 方法

### 1. 枚举确切集合

```text
1. 用与执行相同的选择条件列出目标
2. 计数，并给出可核对的样本（前 5 + 后 5）
3. 列出被**排除**的近邻对象及排除理由
```

第三步最容易被跳过，也最能暴露选择条件的错误。「排除了 X 因为它不匹配 Y」如果说不出来，说明选择条件本身没想清楚。

### 2. 呈现给 decider

```markdown
将对 **N 个** <对象类型> 执行 <动作>：

前 5 个：<列举>
后 5 个：<列举>

**排除**了 <M 个> 近邻对象：<样例及排除理由>

风险：<五维中非最低档的维度>
撤销方式：<具体如何撤销，代价>

批准对这 N 个对象执行？
```

给出计数和边界样本，让 decider 能实际核对。只说「批量处理相关文件」不构成可批准的对象。

### 3. 执行前重新比对

批准与执行之间世界可能变化。执行前用 `checkDeltaApproval()` 比对：

```text
目标集扩大        → TARGET_SET_EXPANDED，重新批准
目标身份改变      → 同样触发（子集 + 身份双重判定）
严格子集          → 不需重新批准
```

**计数相同不代表集合相同**。把 f3 换成 f9 保持数量不变，却作用在从未被批准的对象上。

## 不可枚举的情况

```text
blast_radius == unbounded → 不可枚举（UNBOUNDED_NOT_ENUMERABLE）
```

这是**阻塞发现，不是继续的许可**。正确处理：

1. 缩小选择条件到可枚举集合；
2. 或拆分为多个可枚举的步骤，逐步批准；
3. 若两者都不可行 → `BLOCKED`，说明为何无法界定作用范围。

不可接受的处理：以「范围太大所以只能大致批准」为由跳过枚举。范围大到无法枚举，正是最需要枚举的情形。

## 与 dry-run 的关系

枚举天然产出 dry-run 能力：既然已经列出确切目标集，就可以在不执行的前提下展示「将发生什么」。

```text
枚举 → 呈现 → 批准 → 执行 → 独立读回计数比对
```

最后一步是 E2 证据：执行后重新枚举并计数，与批准的 N 比对。计数不符即使动作「成功」也不能判 SATISFIED。

## 跨领域适用

| 目标 | 目标集 | 枚举方式 |
|---|---|---|
| 整理 3000 个文件 | 文件路径列表 | 按选择条件列出，计数 |
| 给客户群发通知 | 收件人列表 | 列出邮箱，标注排除者 |
| 批量取消订阅 | 订阅项列表 | 列出服务名与账号 |
| 删除历史数据 | 记录范围 | 时间窗 + 计数 + 抽样核对 |

注意后三项都是外部化动作（`externality != private`），required_rung 已被抬到 E4——枚举批准之外还需要外部回执才能判满足。
