# Goal Alignment Card

> 进入 `PLANNING` 前的唯一对齐产物。五段固定，不增不减。
> 长度目标 ≤400 字；它是决策载体，不是文档。

```markdown
## 1. 目标差量

<世界将变成什么样。必须是结果差量，不是要执行的动作。>

主体：<唯一可解析的作用对象>
时间窗：<差量须在何时成立>
scope_version：<N>

## 2. 本轮范围

**范围内**
- <in-scope 项>

**非目标**（同权必填）
- <out-of-scope 项>

**延后**
- <deferred 项，附延后理由>

## 3. 关键假设、约束与 Mandate 缺口

**假设**（未问的槽位）
- <假设> — defeat 条件：<什么现象出现说明它不成立>

**约束**（全程必须成立）
- <不得破坏 X / 不得花钱 / 不得外泄 Y>

**Mandate 缺口**
- <缺失分量>：<后果与需要谁提供>
- 无缺口时写「无」，不留空

## 4. 判据与所需证据

| ID | 类型 | 判据 | required | 上限 | 判定权 |
|---|---|---|---|---|---|
| c-1 | STATE | <可判定的命题> | E2 | E4 | Agent |
| c-2 | JUDGMENT | <依赖人的评价> | E4 | E4 | <acceptor> |

<存在 UNTESTABLE 判据时，必须在此列出并说明上限原因。>

## 5. Residual、风险与批准点

**Residual**：<Agent 不可达的部分；无则写「无」>
- 责任人：<谁>
- 下一动作：<人类可独立执行的最小充分指令>
- 验收方式：<如何确认完成>

**风险**：<五维中非最低档的维度及取值>

**批准点**：<需要 decider 批准的具体事项与目标集枚举>

**本轮终态上限**：<DONE / PARTIAL / UNVERIFIABLE>
```

## 填写规则

1. **第 1 段不得出现动作动词开头**。「实现批量导入」不合格，「运营不再需要每天手工录入 2 万条」合格（`validateGoalShape()` 会拒绝前者）。
2. **第 2 段的「非目标」不得省略**。只写范围内不构成范围。
3. **第 3 段的 Mandate 缺口和第 5 段的 residual 必须在此刻披露**，不能等执行到最后。若 residual 非空，第 5 段末尾的终态上限已确定为 `PARTIAL`。
4. **第 4 段每条判据都必须有类型**。未分类判据不得进入执行。
5. **第 5 段的批准点必须枚举目标集**，不能写「批量处理相关文件」。

## 确认语义

呈现对齐卡后，只接受两种回应：

- **批准当前 goal/scope_version** → 记录 `GOAL_ALIGNED`，进入 `PLANNING`；
- **拒绝并修正** → 回到 `ALIGNING`，按修正重新派生 Frontier。

沉默、「继续」、「好」、带条件同意、执行者自行推断**均不算批准**。用户提出修正意见时，范围变更需走 `SCOPE_CHANGED` 事件（`scope_version` +1，需 decider 同意）。
