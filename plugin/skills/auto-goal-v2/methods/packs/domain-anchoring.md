# 领域锚定

> 命中信号：`DOMAIN_UNFAMILIAR` —— 领域术语或惯例不熟。
> 更新：assumptions、evidence。

## 为什么这是硬需求

规划质量对**术语熟悉度**极度敏感。有实测显示：同一个规划任务，仅把词表换成语义等价但陌生的形式，模型成功率从 62.6% 崩到 0.8%；即使最强推理模型也从 97.8% 掉到 52.8%。

这不是「不太熟练」，而是**规划能力在陌生词表下基本失效**。因此领域不熟时，锚定不是可选的准备工作，而是规划的前置条件。

## 方法

### 1. 先查既有标准，别自造

```text
这个领域已有的标准/规范/清单是什么？
acceptor 自己用的标准是什么？
有没有先例可参照？
```

**优先用 acceptor 的既有标准**。自造标准在判定型判据上是越界（见 `judgment-sampling`），在事实型判据上则往往漏掉领域公认的关键项。

### 2. 术语映射到已知结构

把陌生术语映射到你确实理解的结构上：

```markdown
| 领域术语 | 我的理解 | 映射到 | 置信度 |
|---|---|---|---|
| <术语> | <解释> | <已知概念> | 高/中/低 |
```

**低置信度的映射是 Frontier 候选或查证任务**。带着错误映射规划，产出的计划会在术语层面看起来合理、在实质层面完全错位。

### 3. 事实查证走 worker，不问用户

可查的事实**派 discovery worker 查**（`route()` 会把这类问题归入 `delegated`）：

```text
可查：行业标准内容、法条原文、API 文档、既有实现、公开数据
只有 principal 知道：他们的偏好、内部约定、未公开的历史决策、优先级
```

把可查事实推给用户，是把工作推回去。这条边界由提问判据的第二闭条件强制。

### 4. 用反例验证理解

```markdown
按我的理解，<反例> 在这个领域是不可接受的，因为 <理由>。对吗？
```

在陌生领域，反例是最高效的校准工具：它用一个具体判断暴露整体理解是否对齐，成本远低于让对方通读你的理解。

## 锚定完成的信号

```text
- 关键术语都有映射，且高置信度
- 已找到并阅读 acceptor 或行业的既有标准
- 能给出该领域的反例并被确认
- 能说出这个领域的常见失败模式
```

最后一条是深度检验：说不出常见失败模式，说明只学了词汇没学到结构。

## 锚定不足时的诚实处理

```text
锚定不足 + 判据是 JUDGMENT     → 尽早取样，让 acceptor 校准（不要自评）
锚定不足 + 判据是事实型         → 先派 worker 查证再规划
锚定不足 + 无法查证也无 acceptor → competence 缺口，登记为 residual
```

第三种是 `competence` 分量缺失的典型形态：不是没权限，是做不对。正确终态是有界尝试后 `BLOCKED`，并在交接物中说明需要什么专业能力。

**不可接受**：在术语层面猜测并继续规划。上述实测数据说明这条路的成功率接近随机。
