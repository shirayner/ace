# 分级混合澄清 —— 自决 / 轻档 / 重档 与升级触发器

> 核心：不是所有决策点都值得递给用户，更不是所有点都值得对抗深挖。**三档**：低价值点自己定（自决档），一般点温和引导（轻档），高返工成本点对抗深挖（重档）。用**返工成本 + 惊讶测试**做自动分档。
>
> 本文只管**深度**这一维度（问多狠 / 问不问）。另一正交维度**格式**（怎么问：字母序号、两层选项、分组、多轮）统一收在 `ask-user-guide.md`——任何要问的点都必须守那套契约。

---

## 为什么要三档，而不是两档

- **只有轻/重两档**（都是"问"）：低价值问题也占用户一次点选，问题越堆越多，用户疲劳；等真正的高价值问题出现时，他已经在无脑点了。
- **全程重档**：对每个小点反复质疑，用户疲劳、效率低。
- **全程轻档**：对模糊/高风险需求挖不深，隐含假设漏过，PRD 埋雷。

三档 = **自决档过滤噪声，轻档保效率，重档保深度**。用户的注意力是稀缺资源，分档就是分配它。

---

## 分档判据

对 frontier 里的每个决策点，两步判：

**第一步：错了要返工吗？**（判据表见 `flow.md` Step 2）

- **不要返工** → **自决档**。自己定，记入假设清单，不占提问轮次。
- **要返工** → 进 Ask 通道，走第二步。

**第二步：命中升级触发器吗？**

| 触发条件 | 例子 |
|---|---|
| 多个可行方案且各有取舍 | "登录用手机号还是邮箱还是都要？" |
| 决策依赖用户偏好，你猜不准 | "报表默认按天还是按周聚合？" |
| 范围可能超出/偏离原始诉求 | 用户说"加个搜索"，但没说搜什么、怎么排序 |
| 你正在填补用户没说明的部分 | 用户没提权限，但这功能显然涉及权限 |
| 术语有歧义或被重载 | "账号"到底指 Customer 还是 User？ |
| 答错代价高 / 难回退 | 涉及数据模型、对外接口、合规 |

命中 → **重档**。不命中 → **轻档**。

**判断口诀**：用户此刻看到我对这个点的默认决策会惊讶吗？**会惊讶 + 错了要返工 → 重档。会惊讶但错了好改 → 自决档（记入假设清单，门禁兜底）。**

注意"会惊讶"本身不足以升级——它只说明用户没预料到，不说明代价高。把所有"会惊讶"的点都问一遍，就回到了两档时代的疲劳问题。

---

## 自决档：自己定，记一条

**适用**：错了好改的点——文案、默认值、样式、局部交互、易改的边界处理。

做法：

1. 用最常见/最合理的默认值定下来。
2. 按 `flow.md` 的格式记入**假设清单**：`<场景> → <行为>｜理由｜返工成本`。
3. **不问用户，不占提问轮次。** 这些条目到对齐门禁时一次性亮出来给用户 last call。

两条自检——命中任一说明它不该在自决档，移回 Ask 通道：

- 写不出理由（说明你自己也没想清，只是想跳过）
- 返工成本写到"中"以上

**自决 ≠ 静默。** 定了不记 = 静默假设，是本 skill 最严重的失误：用户永远没机会否决它。

---

## 轻档：引导式澄清

**适用**：错了要返工，但不命中升级触发器的点。

做法：

- 遵守 `ask-user-guide.md` 的**结构化提问契约**（字母序号、label 写行为、description 带边界值和理由、自由输入口、分组合并）。
- 聚焦三类：**目的（purpose）/ 约束（constraints）/ 成功标准（success criteria）**。
- 用户认可推荐值即可快速推进，不纠缠。

示例（轻档，单点）：

```
关于「导出功能」的格式，我建议默认 Excel（.xlsx），因为你的用户多在做数据整理。

Q1. 需要同时支持 CSV / PDF 吗？
  A) 只要 Excel（推荐）— 覆盖数据整理场景，实现成本最低
  B) Excel + CSV — 多一个纯文本格式，方便脚本处理
  C) Excel + CSV + PDF — 加打印/归档场景，但 PDF 排版要额外投入
  （或直接补充你的想法）
```

## 重档：对抗深挖

**适用**：错了要返工，且命中升级触发器的高风险决策点。

切到 `grill-techniques.md`，用决策树遍历 + 术语压测 + 边界反例 + 假设攻破等技法，把这个点彻底问透，再回到主流程 frontier。

重档不是对整个需求，而是**对当前这一个高风险决策点**做深挖。挖完即回轻档节奏。

**用户答不出时不要硬挖**——连续两轮低信息量回答说明追问已失效，改用低保真制品让他批注（`prototyping.md`）。深挖的目的是拿到信息，不是证明你会问。

---

## 档位切换是动态的

同一次需求澄清里，档位随决策点浮动：

```
决策点1(目标与动机)  → 重档（目标错了全盘返工，必须挖透）
决策点2(权限模型)    → 重档（涉及数据模型，难回退）
决策点3(导出格式)    → 轻档（要返工但不复杂，推荐值即可）
决策点4(列表默认排序) → 自决档（改一行代码的事，记入假设清单）
决策点5(按钮文案)    → 自决档（同上）
```

不要给整个会话贴一个固定档位。**逐点判断。**

健康的比例大致是：重档少数几个、轻档若干、**自决档通常最多**。如果自决档一个都没有，说明你在把低价值问题往用户身上推；如果重档占了一半以上，说明范围可能过大，回 `flow.md` Step 1 考虑拆需求。
