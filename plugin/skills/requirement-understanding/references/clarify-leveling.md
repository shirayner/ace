# 分级混合澄清 —— 轻档 / 重档 与升级触发器

> 核心：不是所有澄清点都值得对抗深挖。默认用轻档（引导式，高效），只在高风险点升级为重档（对抗深挖，彻底）。用**惊讶测试**做自动升级开关。
>
> 本文只管**深度**这一维度（问多狠：轻档 / 重档）。另一正交维度**格式**（怎么问：选项化、推荐项、分组、多轮、通道降级）统一收在 `ask-user-guide.md`——任何档位的提问都必须守那套契约。

---

## 为什么分级

- **全程重档**（grill-me 式对抗打断）：对每个小点都反复质疑，用户疲劳、效率低。
- **全程轻档**（温和引导）：对模糊/高风险需求挖不深，隐含假设漏过，PRD 埋雷。

分级 = 默认轻档保效率，命中高风险自动切重档保深度。

---

## 升级触发器（惊讶测试）

一个决策点，若命中以下任一条 → **升级重档**：

| 触发条件                   | 例子                                     |
| -------------------------- | ---------------------------------------- |
| 多个可行方案且各有取舍     | "登录用手机号还是邮箱还是都要？"         |
| 决策依赖用户偏好，你猜不准 | "报表默认按天还是按周聚合？"             |
| 范围可能超出/偏离原始诉求  | 用户说"加个搜索"，但没说搜什么、怎么排序 |
| 你正在填补用户没说明的部分 | 用户没提权限，但这功能显然涉及权限       |
| 术语有歧义或被重载         | "账号"到底指 Customer 还是 User？        |
| 答错代价高 / 难回退        | 涉及数据模型、对外接口、合规             |

**判断口诀**：用户此刻看到我对这个点的默认决策会惊讶吗？会 → 重档。

不命中 → 轻档。

## 结构化提问契约（格式细则见另文）

> 这是**格式**层面的硬约定，与"轻档/重档"（深度层面）正交。无论哪个档位、无论用什么通道，向用户提问都必须守同一套不变量：选项化 + 推荐项置首 + 保留自由输入口、单轮 ≤4 问、信息在正文不塞选项、澄清与审批分开调用、每轮答完实时更新、独立点合并 / 依赖或高风险点串行、有 `AskUserQuestion` 优先用无则降级等价 markdown。

**完整规范（含两种提问模式、六条不变量、节奏分组、通道降级、反模式与好坏例）→ 读 `ask-user-guide.md`。** 本文不再重复，只强调一句：**禁止一次抛一大堆点、纯文本、要用户作文回复。**

## 轻档：引导式澄清

**适用**：需求基本清晰、决策点低风险、事实性补全。

做法：

- 遵守 `ask-user-guide.md` 的**结构化提问契约**（选项化、推荐项、自由输入口、分组合并）。
- 聚焦三类：**目的（purpose）/ 约束（constraints）/ 成功标准（success criteria）**。
- 用户认可推荐值即可快速推进，不纠缠。

示例（轻档，单点）：

```
关于「导出功能」的格式，我建议默认 Excel（.xlsx），因为你的用户多在做数据整理。
需要同时支持 CSV / PDF 吗？
  A) 只要 Excel（推荐）
  B) Excel + CSV
  C) Excel + CSV + PDF
  （或直接补充你的想法）
```

## 重档：对抗深挖

**适用**：命中升级触发器的高风险决策点。

切到 `grill-techniques.md`，用决策树遍历 + 术语压测 + 边界反例 + 假设攻破等技法，把这个点彻底问透，再回到主流程 frontier。

重档不是对整个需求，而是**对当前这一个高风险决策点**做深挖。挖完即回轻档节奏。

---

## 档位切换是动态的

同一次需求澄清里，档位随决策点浮动：

```
决策点1(目标)  → 重档（目标必须挖透）
决策点2(导出格式) → 轻档（低风险，推荐值即可）
决策点3(权限模型) → 重档（数据模型，答错代价高）
决策点4(按钮文案) → 轻档 / 甚至自己定
```

不要给整个会话贴一个固定档位。**逐点判断**。
