# 需求理解 Skill

**核心信念：对齐优先于一切。理解对了，后面才不白做。**

把一个需求（从零想法 / 已有 PRD / 半成品）建模成决策树、逐点澄清，直到与用户达成**可确认的共识**。本 skill 只做一件事——**把需求理解透、与用户对齐**。对齐后的产出（五要素 / glossary / 已定决策）留在会话上下文，下游拿它做什么（写 PRD、出技术方案、直接开发）与本 skill 无关。

**进料模式（读完输入先判定，不进门问用户）**：从零构思（发散建树，防下沉——别编用户没说的方案/规则）/ 已有约束或 PRD（抽取既定内容填树，防篡改——既定业务规则原样保留，只澄清 gap/冲突/歧义）/ 半成品（两者混合）。分不清按半成品走。详见 `references/flow.md` 的 Step 0 Intake。

---

## 定位

- **本 skill 做什么**：识别进料模式 → 范围检查 → 建决策树（从零发散 / 已有抽取 / 半成品混合）→ 逐点澄清（命中高风险升级对抗深挖）→ frontier 清空 → 复述五要素 → 调 AskUserQuestion 对齐。
- **本 skill 不做什么**：不假设下游用途，不代替下游动作。对齐通过 = 本 skill 完成。
- **产出**：五要素 + glossary + 已定决策，留在会话上下文，供任意后续场景取用。

---

## 硬门禁（不可跳过）

<HARD-GATE name="对齐门禁">
对用户宣告"需求已对齐"前，目标对齐必须通过。
证据 = AskUserQuestion 已调用，且用户回复了确认。
无证据 = 禁止宣告对齐。
</HARD-GATE>

**违反形式 = 违反精神。** "这需求很清楚了" = 你以为的清楚，不是对齐。"上一个需求对齐过了" = 新需求要新对齐。

### Red Flags —— 正在跳过澄清/对齐

以下念头一旦出现，立即停手，回到澄清：

| 你的念头 | 真相 |
|----------|------|
| "这需求很简单" | 简单 = 隐含决策被忽略，恰恰最该澄清 |
| "用户说得很清楚了" | 说清楚 ≠ 你理解 100% 正确 |
| "先往下走边做边对" | 对齐在动作之前；错误理解会锚定后续方向 |
| "我大概知道用户要什么" | 大概 ≠ 验证，调 AskUserQuestion 确认 |
| "补上这个假设就能对齐了" | 你正在替用户做决定 → 触发惊讶测试，去问 |
| "写了对齐内容了" | 写了 ≠ 调了工具，缺 AskUserQuestion 无效 |

### 惊讶测试

**一句话判断**：如果用户此刻看到我的决策会惊讶 → 暂停，去问。

触发场景：多个方案各有取舍 / 决策依赖用户偏好 / 范围超出原始诉求 / 正在填补用户没说明的部分 / 术语有歧义。

## 主流程

**入口** → 读 `references/flow.md`（含完整状态机：scope→决策树→追问→收敛）。

按需加载：

| 需要做什么 | 读哪个文件 |
|------------|-----------|
| 走完整理解流程（识别进料→scope→决策树→追问→收敛） | `references/flow.md` |
| 判断某个澄清点用轻档还是重档 | `references/clarify-leveling.md` |
| 向用户提问的格式契约（通道无关、选项化、分组、多轮、审批） | `references/ask-user-guide.md` |
| 升级到对抗深挖后，具体怎么问 | `references/grill-techniques.md` |
| 收敛后复述五要素 + 执行对齐门禁 | `references/alignment-gate.md` |

**收敛判据**：不是"问够 N 个"，而是**决策树 frontier 清空**——每个待定分支都已解、没有被静默假设的东西。用户可随时喊停接受现状。

---

## 产出（随聊随记）

理解过程中维护三样，既是对齐依据，也是留给后续场景的成果：

- **已定决策**：每个决策点的最终答案 + 归属（用户定 / 用户认可推荐值）。
- **术语表 glossary**：需求里的关键术语精确定义（尤其歧义/重载词）。
- **待答清单**：frontier 里还没解的点。

对齐门禁通过时，这三样固化进会话上下文。

---

## 完成

对齐门禁通过后：
1. 告知用户："需求已对齐。五要素 / glossary / 已定决策已就绪。"
2. 本 skill 完成，不代替下游做任何事。

---

## 状态与恢复

长需求会话跨轮次时，用"已定决策 + glossary + 待答清单"跟踪进度。

用户说"继续"时：
1. 回看已定决策与待答清单，确认 frontier 是否清空。
2. 未清空 → 从未解分支继续追问。
3. 已过对齐门禁 → 本 skill 已完成。

---

## 进度心跳

- 完成 scope / 完成一批澄清 / 收敛 → 一句话报告。
- 连续多次工具调用无文本 → 插入说明当前在做什么。
- 方向变化（从轻档升级到重档、发现需求需拆分）→ 立即告知用户。
