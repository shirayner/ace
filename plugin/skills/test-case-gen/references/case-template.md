## 标准表格模板

适用于大多数场景，结构化程度高，便于管理和追踪。

```markdown
## 测试用例 — [模块/功能名称]

| ID | 优先级 | 场景 | 前置条件 | 操作步骤 | 预期结果 | 设计方法 |
|----|--------|------|---------|---------|---------|---------|
| TC-001 | P0 | ... | ... | 1. ... 2. ... | ... | ... |
```

### 字段说明

| 字段 | 说明 | 示例 |
|------|------|------|
| **ID** | 唯一标识，格式 `TC-{模块缩写}-{序号}` | TC-ORD-001 |
| **优先级** | P0/P1/P2/P3（风险驱动） | P0 |
| **场景** | 一句话描述测试什么 | 正常下单-余额充足 |
| **前置条件** | 执行前系统必须处于的状态 | 用户已登录；余额≥订单金额 |
| **操作步骤** | 具体操作序列（编号） | 1. 选择商品 2. 点击购买 3. 确认支付 |
| **预期结果** | 可验证的具体结果（非模糊描述） | 订单状态=已支付；余额减少100元 |
| **设计方法** | 该用例来源于哪种设计方法 | 等价类/边界值/状态机/BDD |

## BDD 场景模板

适用于用户交互流程，更贴近业务语言。

```gherkin
Feature: [功能名称]
  [功能描述，一句话]

  Background:
    Given [所有场景共享的前置条件]

  @P0
  Scenario: [正常场景名称]
    Given [前置条件]
    When [操作]
    Then [预期结果]

  @P1
  Scenario: [异常场景名称]
    Given [前置条件]
    When [异常操作]
    Then [错误处理预期]

  @P1
  Scenario Outline: [参数化场景]
    Given 用户类型为 <user_type>
    When 操作 <action>
    Then 结果为 <result>

    Examples:
      | user_type | action | result |
      | 普通用户  | 购买   | 成功   |
      | 黑名单   | 购买   | 拒绝   |
```

## 完整示例：会员保级功能

### 需求摘要
> 黑钻会员在保级周期到期时，根据消费金额、保级分数、风控状态决定是否保级。

### 测试策略
- 采用方法: 判定表 + 状态机 + 边界值
- 覆盖维度: 正常保级 / 降级场景 / 边界金额 / 白名单 / 风控拦截
- 总用例数: 18 条（P0: 4 / P1: 7 / P2: 5 / P3: 2）

### 用例

| ID | 优先级 | 场景 | 前置条件 | 操作步骤 | 预期结果 | 设计方法 |
|----|--------|------|---------|---------|---------|---------|
| TC-RET-001 | P0 | 正常保级-满足所有条件 | 黑钻用户，消费≥阈值，分数≥阈值，无风控 | 触发保级评估 | 保级成功，等级不变 | 判定表规则1 |
| TC-RET-002 | P0 | 降级-消费不足 | 黑钻用户，消费<阈值 | 触发保级评估 | 降级为白金 | 判定表规则2 |
| TC-RET-003 | P0 | 强制降级-风控拦截 | 黑钻用户，消费≥阈值，风控标记=高危 | 触发保级评估 | 强制降级，记录原因 | 判定表规则3 |
| TC-RET-004 | P0 | 边界金额-恰好等于阈值 | 黑钻用户，消费=阈值（精确到分） | 触发保级评估 | 保级成功 | 边界值 |
| TC-RET-005 | P1 | 边界金额-差1分不够 | 黑钻用户，消费=阈值-0.01 | 触发保级评估 | 降级 | 边界值 |
| TC-RET-006 | P1 | 白名单用户-绕过金额检查 | 黑钻用户，在白名单中，消费=0 | 触发保级评估 | 保级成功 | 等价类 |
| TC-RET-007 | P1 | 白名单+功能关闭 | 黑钻用户，在白名单中，保级功能开关=关 | 触发保级评估 | 需确认：白名单是否绕过开关？ | 边界值 |
| ... | | | | | | |

### 覆盖矩阵

| AC | 描述 | 用例 | 状态 |
|----|------|------|------|
| AC-1 | 满足条件保级成功 | TC-RET-001, 004, 006 | ✅ |
| AC-2 | 不满足条件降级 | TC-RET-002, 005 | ✅ |
| AC-3 | 风控拦截强制降级 | TC-RET-003 | ✅ |
| AC-4 | 白名单特殊处理 | TC-RET-006, 007 | ⚠️ 需确认语义 |

### 风险备注
- ⚠️ TC-RET-007 暴露了需求歧义：白名单是否应绕过功能总开关？需与产品确认。
- ⚠️ 未覆盖并发场景（同一用户保级评估期间等级被手工修改）

## 输出质量检查清单

生成用例后自检：

- [ ] 每个 AC 至少有 1 个对应用例？
- [ ] 异常路径用例数 ≥ 正常路径用例数？
- [ ] 边界值是否覆盖了所有数值/时间边界？
- [ ] P0 用例是否覆盖了核心业务流程？
- [ ] 预期结果是否足够具体（可机械验证）？
- [ ] 是否发现了需求歧义或遗漏？（这是好事！）
- [ ] 是否有重复或冗余的用例？（合并）
- [ ] 非功能维度是否考虑了？（性能/安全/兼容）
