# 敏捷拆分工作流（prd-breakdown）

## 概述

**目标**：快速生成 PRD 的敏捷拆分报告，无需深度评审

**工作流**：按照 5 阶段结构化流程进行拆分

---

## 5 阶段拆分流程

### ✅ 阶段 1：PRD 理解

识别并确认：
- 业务目标 - 这个 PRD 要解决什么问题？
- 用户角色 - 涉及哪些角色？
- 核心场景 - 最核心的用户场景是什么？
- 范围边界 - 在本期内要完成什么，不完成什么？

**输出**：PRD 摘要和范围说明

---

### ✅ 阶段 2：Epic 识别

根据业务价值识别主要业务目标：
- 将 PRD 中的主要业务需求归纳为 Epic
- 每个 Epic 代表一条业务价值线
- 标注 Epic 的优先级（P0/P1/P2）
- 标注 Epic 的依赖关系

**输出**：Epic 列表（业务价值导向）

---

### ✅ 阶段 3：Feature 拆分

识别每个 Epic 下的完整产品能力：
- 将每个 Epic 分解为若干 Feature
- 每个 Feature 是一个独立的可产品化的能力
- 标注 Feature 的优先级和依赖关系
- 列出非功能需求（NFR: 性能、安全、扩展性等）

**输出**：Feature 列表（产品能力导向）

---

### ✅ 阶段 4：Story 拆分

拆分最小可独立交付的用户故事：
- 每个 Story 遵循"用户故事"格式：`As a [角色] I want [功能] so that [价值]`
- 标注验收标准（Acceptance Criteria）
- 标注任何关键的技术约束或风险
- 识别故事间的依赖关系

**输出**：Story 列表（用户故事格式，含验收标准）

---

### ✅ 阶段 5：质量校验

验证拆分的完整性和可执行性：
- ✅ 是否覆盖了 PRD 的所有功能需求？
- ✅ 是否标注了所有关键的非功能需求？
- ✅ 故事间的依赖关系是否清晰？
- ✅ 是否有遗漏或重复的故事？
- ✅ 每个故事的粒度是否合适？

**输出**：质量校验结果和改进建议

---

## 输出文件格式

生成的报告文件名：`prd_review_breakdown_{title}_{timestamp}.md`

### 报告结构

```markdown
# PRD 敏捷拆分报告

## PRD 摘要与范围分析
- 业务目标
- 用户角色
- 核心场景
- 范围边界

## Epic 列表（业务价值导向）
- Epic 1
  - 优先级: P0
  - 依赖: 无
- Epic 2
  - 优先级: P1
  - 依赖: Epic 1
...

## Feature 列表（产品能力导向）
- Feature 1.1 (归属 Epic 1)
  - 优先级: P0
  - 依赖: 无
- Feature 1.2 (归属 Epic 1)
  - 优先级: P0
  - 依赖: Feature 1.1
...

## Story 列表（用户故事格式）
- Story 1.1.1 (归属 Feature 1.1)
  - 用户故事: As a [角色] I want [功能] so that [价值]
  - 验收标准:
    - AC 1: ...
    - AC 2: ...
  - 技术约束: ...
  - 依赖: 无
...

## 非功能需求（NFR）
- 性能目标
- 安全要求
- 扩展性考虑
- 其他 NFR
...

## 依赖关系分析
- Epic 间依赖
- Feature 间依赖
- Story 间依赖

## 不确定性和推断标注
- 推断项：因信息不足而由 AI 推断的内容
- 假设项：为了保证可执行性而引入的假设

## 质量校验结果
- 完整性检查
- 粒度检查
- 依赖关系检查
- 改进建议
```

---

## 适用场景

- 快速理解 PRD 的功能划分和优先级
- 为后续的角色特定评审准备（如工程师、测试、产品角度）
- 检查需求的完整性和依赖关系
- 指导产品、研发、测试团队制定实现计划
- 用于技术复杂度评估和工作量估算

---

## 使用方法

```bash
/prd-review prd-breakdown
```

然后按提示提供 PRD 内容，Skill 将按 5 阶段流程直接生成拆分报告。

**不会执行的步骤**：
- ❌ 不选择特定的评审角色
- ❌ 不进行多轮对话深度评审
- ❌ 不生成角色特定的评审报告

**输出方式**：
- ✅ 生成敏捷拆分报告（markdown 格式）
- ✅ 保存到 `~/.prd-review/{PRD_TITLE}/prd_review_breakdown_{title}_{timestamp}.md`
