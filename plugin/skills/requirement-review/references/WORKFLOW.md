# 完整工作流详细说明

## 工作流步骤

### Step 1-2: 收集输入

**您的操作**：
1. 提供 PRD 来源（文件路径、链接或直接粘贴）
2. 我加载 PRD 内容

**我的操作**：
```
文件处理流程：
1. 检测来源类型（本地文件/链接/文本）
2. 加载或解析 PRD 内容
3. 提取标题、描述、核心需求
4. 显示摘要供确认
```

**预期输出**：PRD 摘要 + 基本信息确认

**📌 注意**：生成的文件名中 title 部分将使用英文格式。

---

## Step 3: 选择评审角色

**说明**：评审角色必须从角色配置（roles.json）中选择，不支持自定义或其他角色。

**我的操作**：

1. **加载并显示可用角色列表**

从 `resources/roles.json` 读取所有已启用的角色（enabled: true），输出格式如下：

```
📋 可用的评审角色：

  [1] backend_member - 后端研发(会员)
      类型: custom
      职责: 会员系统后端的技术设计、架构决策、性能优化、数据安全

      📄 评审标准: references/backend_member/standard.md
      📋 报告模板: references/backend_member/template.md

[共 1 个角色可用]
```

2. **加载选定角色的标准和模板**

用户选择角色后，我将：
- 读取 `references/{role_id}/standard.md` - 评审标准
- 读取 `references/{role_id}/template.md` - 报告模板结构
- 确认加载成功

**您的操作**：

输入角色编号或角色 ID（如：`1` 或 `backend_member`）进行选择。

**角色选择规则**：
- ✅ 只能选择已启用的角色（enabled: true）
- ✅ 只能选择从 `roles.json` 加载的角色
- ✅ 支持编号选择（如 1）或 ID 选择（如 backend_member）
- ❌ 不能自定义或输入其他角色

**选择确认**：

一旦您选择了角色，我将显示：

```
✅ 已选择角色: backend_member (后端研发-会员)

📋 评审标准已加载
📄 报告模板已加载
📌 模板结构:
   - PRD 基本信息 (名称/时间/版本/评审人)
   - Epic 级需求分析
   - 功能点详情
   - 问题清单 (P0/P1 优先级)
   - 推断与假设缺口

准备开始评审...
```

---

## Step 4: 敏捷拆分

**目标**：将 PRD 分解为可管理的粒度

**我的操作**：
```
敏捷拆分流程：
1. 识别用户故事（User Story）
2. 提取功能特性（Epic/Feature）
3. 识别非功能需求（NFR: 性能、安全、扩展性）
4. 标注关键约束和风险

输出格式示例：
- Epic: 用户账户管理
  - Feature: 注册流程
    - Story: 邮箱验证
  - Feature: 登录流程
    - Story: 密码重置

- Non-Functional: 性能目标 < 100ms
```

**验证问题**：
- 是否遗漏了异常场景？
- 依赖关系是否清晰？

---

## Step 5: 多轮对话评审

**我的角色**：作为选定的 [角色] 对 PRD 进行深度评审

**评审维度**：
- 根据加载的标准文档进行深度评审

**您可以提问**：
- "这个流程是否完整？"
- "有什么潜在的风险或遗漏？"
- "技术实现的复杂度如何？"
- "是否有可能被用户误用？"
- "性能目标是否合理？"
- 或任何特定于当前评审角色的问题

**如何结束**：输入 `done` 结束对话，进入报告生成阶段

**我的承诺**：
- 基于选定角色的专业视角回答
- 指出非显而易见的问题
- 提供可操作的建议
- 对于自定义角色，遵循加载的标准和最佳实践

---

## Step 6-7: 报告生成和验证

**我的操作**：

1. **加载角色模板并解析其结构**

从 `references/{role_id}/template.md` 读取模板，识别其核心字段（通过 markdown 结构识别）：
- PRD 基本信息块（名称、时间、版本、评审人）
- Epic 级分组（识别 `## 🌈 Epic` 或类似标记）
- 功能点子级（识别 `### ✨功能点` 或类似标记）
- 问题清单块（识别 `#### 🐞问题清单` 表格）
- 推断/假设块（识别 `#### 🔍推断 / 假设缺口`）

2. **从工作流输出中提取相关内容**

根据模板的字段结构，从前面的工作流中（敏捷拆分、多轮对话、风险识别等）提取：
- **对应 Epic 字段** → 敏捷拆分中的 Epic 信息
- **对应功能点字段** → 敏捷拆分中的 Feature 信息
- **对应问题清单** → 多轮对话评审中识别的问题（优先级 P0/P1）
- **对应推断/假设** → 多轮对话中的推断和不确定项

3. **动态映射和填充**

**映射原则**（可扩展，适用于任何角色模板）：
```
工作流输出              →  模板字段
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
敏捷拆分 Epic          →  模板中的 Epic 章节
敏捷拆分 Feature       →  模板中的功能点章节
多轮对话问题 (P0/P1)   →  模板中的问题清单表格
多轮对话推断/假设      →  模板中的推断/假设缺口
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

**填充策略**：
- ✅ 只填充模板中已定义的字段
- ✅ 优先级匹配 (P0/P1 标签必须映射到问题清单)
- ✅ 不用全部填入工作流内容，只提取与模板相关的部分
- ✅ 保持模板的原始格式和风格

4. **执行验证检查**

（见 references/CHECKLIST.md）

**预期输出**：符合角色模板结构的评审报告

**如验证未通过**：返回 Step 5 重新分析或补充信息

---

## Step 8: 保存输出

根据所使用的子命令，报告保存为不同的格式：

- **prd-review**（默认）：`prd_review_full_{title}_{timestamp}.md`
- **prd-breakdown**：`prd_review_breakdown_{title}_{timestamp}.md`
- **prd-analyze**：无文件输出（仅对话）

**输出路径**：用户主目录 `~/.prd-review/{PRD_TITLE}/`
