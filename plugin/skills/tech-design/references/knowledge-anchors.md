# 知识锚点映射表

当用户描述的系统匹配已知模式时，通过映射快速识别系统类型，并引导关键决策。

---

## 使用方式

1. 用户描述系统 → 匹配下表中最接近的系统类型
2. 加载该类型的"关键决策焦点"
3. 在阶段 2-5 中优先追问这些关键决策

---

## 如何使用知识锚点

**示例对话**：

用户："我想做一个类似内部知识库的东西，用 LLM 来回答问题"

→ 匹配：**RAG/知识库**

→ 优先追问：
1. 知识来源是什么格式？更新频率？
2. RAG vs 长上下文：文档总量多大？能否塞进上下文窗口？
3. 切块策略：按段落？按语义？固定大小？
4. 检索方式：关键词、向量、还是混合？
5. 引用溯源：用户是否需要看到原文出处？
6. 质量保证：如何检测/处理幻觉？

→ 后续可选追问（根据回答展开）：
- 多租户知识隔离？
- 实时性要求（新文档多久可查？）？
- 成本预算（每次查询的 Token 消耗）？

## 无匹配策略

当用户系统不匹配任何已知模板时：

1. **不强行归类** — 明确告知用户"这是非典型系统"
2. **回退到通用框架** — 使用灵魂六问 + 质量属性取舍作为引导主线
3. **从数据流入手** — 追问"数据从哪来？经过什么处理？给谁看？"
4. **提取组件** — 系统可能由多个已知模式的子组件构成，分别匹配

---

## 多匹配策略

当用户系统跨越多个模板时（如"带 AI Agent 的电商系统"）：

1. **识别主模板和辅模板** — 系统的核心价值链属于哪个模板？
2. **合并关键决策焦点** — 从所有匹配的模板中提取关键决策，去重后按优先级排序
3. **标注冲突点** — 不同模板的建议可能冲突（如电商要求强一致但 Agent 要求低延迟），显式暴露
4. **分层处理** — 核心交易链路用主模板约束，AI 增强部分用辅模板约束
