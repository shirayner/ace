# 架构审查清单

对已完成的设计方案进行系统化审查，补齐 AI 生成方案的常见盲点。

---

## 使用方式

1. 确定系统关注的质量属性（Top 3）
2. 对照相关类别的检查项逐条过
3. 不必全部检查——匹配审查深度与业务关键性

---

## 一、数据一致性检查

### 幂等性
- [ ] 重复请求是否产生重复副作用？（重复扣费、重复创建）
- [ ] 是否有幂等键设计？
- [ ] 重试场景下数据是否安全？

### 事务边界
- [ ] 哪些操作需要在同一事务中？
- [ ] 跨服务操作的一致性如何保证？（Saga/Outbox/补偿）
- [ ] 分布式事务是否可以降级为最终一致？

### 并发控制
- [ ] 同一数据的并发写入如何处理？
- [ ] 是否有乐观锁/悲观锁策略？
- [ ] 读-改-写场景是否存在竞态？

### 数据生命周期
- [ ] 数据保留策略是否明确？
- [ ] 过期数据如何清理？
- [ ] 逻辑删除 vs 物理删除？

---

## 二、韧性检查

### 超时
- [ ] 所有外部调用是否设置超时？
- [ ] 超时值是否合理？（递归链路中层层递减）
- [ ] 超时后的处理逻辑？

### 重试
- [ ] 重试策略：指数退避 + 抖动？
- [ ] 重试次数上限？
- [ ] 重试前提：操作是否幂等？
- [ ] 重试预算：是否限制总重试比例？

### 熔断
- [ ] 依赖方长时间故障时是否有熔断？
- [ ] 熔断后的降级策略？
- [ ] 半开状态的恢复探测？

### 降级
- [ ] 核心功能 vs 非核心功能是否分类？
- [ ] 非核心功能异常时是否影响核心功能？
- [ ] 降级策略是否预定义（而非临时决定）？

### 资源限制
- [ ] 队列是否有容量上限？（防无界增长）
- [ ] 连接池大小是否合理？
- [ ] 内存使用是否有上限？

---

## 三、可扩展性检查

### 热点
- [ ] 是否存在热点 Key？（如大V、热门商品）
- [ ] 分片策略是否均匀？
- [ ] 热点数据是否有本地缓存/打散策略？

### 扇出
- [ ] 是否存在扇出爆炸？（1 请求触发 N 个下游调用）
- [ ] 扇出是否有上限？
- [ ] 扇出失败时的处理？

### 查询效率
- [ ] 是否存在 N+1 查询？
- [ ] 大结果集是否分页？
- [ ] 慢查询是否有优化（索引、缓存、异步）？

### 尾延迟
- [ ] P99 延迟是否可接受？
- [ ] 长尾是什么原因？（GC、锁竞争、慢依赖）
- [ ] 是否有超时快速失败机制？

---

## 四、安全检查

### 认证与授权
- [ ] 所有 API 是否有认证？
- [ ] 授权检查是否细粒度？（不只是"已登录"）
- [ ] Token/Session 过期策略？

### 输入校验
- [ ] 所有外部输入是否校验？
- [ ] 是否防 SQL 注入/XSS？
- [ ] 文件上传是否限制类型和大小？

### 数据安全
- [ ] 敏感数据是否加密存储？
- [ ] 传输是否使用 TLS？
- [ ] 日志中是否脱敏？

### 多租户
- [ ] 数据隔离是否完整？（所有查询是否带租户过滤）
- [ ] 是否存在跨租户数据泄露路径？
- [ ] 资源是否有租户级限制？

---

## 五、AI 系统专项检查

### 模型可靠性
- [ ] 模型调用失败的降级方案？
- [ ] 模型响应超时的处理？
- [ ] 多模型故障转移（fallback 到备用模型）？

### 成本控制
- [ ] 单次请求的 Token/成本上限？
- [ ] 日/月成本预算上限？
- [ ] 超预算时的处理策略？

### 质量保证
- [ ] 如何检测模型输出质量退化？
- [ ] 是否有评估框架（eval）？
- [ ] 幻觉检测机制？
- [ ] 引用/溯源是否可验证？

### 安全防护
- [ ] Prompt 注入防护？
- [ ] 模型输出是否校验后再执行？（工具调用安全）
- [ ] 用户输入是否有内容安全过滤？

### Agent 控制
- [ ] 循环是否有步数上限？
- [ ] 工具调用是否有副作用隔离？
- [ ] 长任务是否有检查点（可恢复）？
- [ ] 多 Agent 扇出是否有上限？

---

## 六、可观测性检查

### 日志
- [ ] 关键路径是否有结构化日志？
- [ ] 错误日志是否包含足够上下文？
- [ ] 日志级别是否可动态调整？

### 指标
- [ ] 核心 SLI 是否有监控？（延迟、错误率、吞吐）
- [ ] 告警阈值是否合理？
- [ ] 是否有 Dashboard？

### 链路追踪
- [ ] 跨服务调用是否可追踪？
- [ ] TraceID 是否贯穿全链路？

---

## 七、演进性检查

### 可逆性
- [ ] 哪些决策是不可逆的？成本有多大？
- [ ] 数据模型变更的迁移成本？
- [ ] 是否有灰度/回滚机制？

### 依赖管理
- [ ] 外部依赖是否有抽象层隔离？
- [ ] 更换依赖的成本？
- [ ] 依赖升级的兼容策略？

### 技术债
- [ ] 有意引入的技术债是否记录？
- [ ] 是否有偿还计划/触发条件？

---

## 审查深度适配

| 系统重要性 | 审查范围 | 时间投入 |
|-----------|---------|---------|
| 核心/支付级 | 全部七类 | 深入每项 |
| 重要业务 | 一~五类 | 重点项深入 |
| 一般功能 | 一~三类 | 快速过检查项 |
| 内部工具 | 一+三类 | 最低限度 |
