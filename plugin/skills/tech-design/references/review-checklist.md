# 架构审查清单

对已完成的设计方案进行系统化审查，补齐 AI 生成方案的常见盲点。

---

## 使用方式

1. 确定系统关注的质量属性（Top 3）
2. 对照相关类别的检查项逐条过
3. 不必全部检查——匹配审查深度与业务关键性

---

## 一、数据一致性检查

- [ ] 重复请求是否产生重复副作用？是否有幂等键？
- [ ] 哪些操作需要在同一事务中？跨服务一致性如何保证？
- [ ] 同一数据的并发写入如何处理？读-改-写是否存在竞态？
- [ ] 数据保留策略是否明确？过期数据如何清理？

---

## 二、韧性检查

- [ ] 所有外部调用是否设置超时？超时值是否层层递减？
- [ ] 重试策略：指数退避+抖动？操作是否幂等？重试预算是否限制？
- [ ] 依赖方长时间故障时是否有熔断？熔断后的降级策略？
- [ ] 核心功能 vs 非核心功能是否分类？非核心异常是否影响核心？
- [ ] 队列/连接池/内存是否有容量上限？

---

## 三、可扩展性检查

- [ ] 是否存在热点 Key？分片策略是否均匀？
- [ ] 是否存在扇出爆炸？扇出是否有上限？
- [ ] 是否存在 N+1 查询？大结果集是否分页？
- [ ] P99 延迟是否可接受？长尾原因是什么？

---

## 四、安全检查

- [ ] 所有 API 是否有认证？授权检查是否细粒度？
- [ ] 所有外部输入是否校验？是否防注入/XSS？
- [ ] 敏感数据是否加密存储？传输是否 TLS？日志是否脱敏？
- [ ] 多租户数据隔离是否完整？是否存在跨租户泄露路径？

---

## 五、AI 系统专项检查

- [ ] 模型调用失败的降级方案？多模型故障转移？
- [ ] 单次请求 Token/成本上限？日/月预算上限？超预算处理？
- [ ] 如何检测模型输出质量退化？幻觉检测机制？
- [ ] Prompt 注入防护？模型输出是否校验后再执行？
- [ ] Agent 循环步数上限？工具调用副作用隔离？多 Agent 扇出上限？

---

## 六、可观测性检查

- [ ] 关键路径是否有结构化日志？错误日志是否包含足够上下文？
- [ ] 核心 SLI 是否有监控？告警阈值是否合理？
- [ ] 跨服务调用是否可追踪？TraceID 是否贯穿全链路？

---

## 七、演进性检查

- [ ] 哪些决策是不可逆的？成本有多大？
- [ ] 外部依赖是否有抽象层隔离？更换成本？
- [ ] 有意引入的技术债是否记录？是否有偿还触发条件？

---

## 审查深度适配

| 系统重要性 | 审查范围 | 时间投入 |
|-----------|---------|---------|
| 核心/支付级 | 全部七类 | 深入每项 |
| 重要业务 | 一~五类 | 重点项深入 |
| 一般功能 | 一~三类 | 快速过检查项 |
| 内部工具 | 一+三类 | 最低限度 |
