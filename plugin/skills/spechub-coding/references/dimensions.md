# 分析维度

按需 Read。分析产物不确定性时参考，聚焦实际不确定的部分。

---

## COMPREHEND 阶段分析维度

| 维度 | 关注点 |
|------|--------|
| 产物完整性 | 平台产物是否覆盖所有场景？有无遗漏？ |
| 产物一致性 | PRD 与 architecture 是否一致？contracts 与 proposal 是否匹配？ |
| 产物与现状冲突 | 产物方案与现有代码/架构是否冲突？ |
| 功能完整性 | 核心流程 + 边界 + 异常 |
| 数据关切 | 数据来源、格式、量级、一致性 |
| 边界异常 | 并发、超时、重试、幂等、降级 |
| 集成依赖 | 上下游服务、外部 API、中间件 |

## DESIGN 阶段澄清维度

| 维度 | 关注点 |
|------|--------|
| 架构决策 | 分层、模式选择、关注点分离 |
| 技术选型 | 框架/库/中间件的选择及理由 |
| 接口设计 | 契约定义、版本策略、兼容性 |
| 数据状态 | 存储选型、schema 设计 |
| 性能可靠性 | SLA 目标、容量规划 |

## 必要性审计维度

| 维度 | 关注点 |
|------|--------|
| 最简实现基准 | 对每个功能点：最简实现是什么？当前方案多出的复杂度由什么需求驱动？ |
| YAGNI 检测 | 产物中是否存在"以后可能需要"驱动的功能？ |
| 新建 vs 扩展 | 现有模块是否可通过 ≤5 个方法级变更达成同一目标？如果是，新建=过度设计 |
| 分离驱动力 | "逻辑不同"不是分离理由。真正驱动力：独立部署、故障隔离、不同数据生命周期、量级差异 SLA |

## 元认知触发器

分析时强制回答（内部思考）：
1. 返工成本最高的误解是什么？
2. 什么让我仍不确定？
3. 如果用最简方案实现，用户会满意吗？
4. 我的结论是否被产物的 [新增] 标签锚定了？
