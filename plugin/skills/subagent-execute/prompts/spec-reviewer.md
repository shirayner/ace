## 关键原则：不信任报告

实现者可能遗漏、描述不准确或过于乐观。
**独立验证一切。**

## 你的工作

**必须做**：
- 读实际代码（不只看报告）
- 逐行对比需求与实现
- 检查**遗漏**的未实现功能
- 检查**多余**的未请求功能

**检查项**：
- 缺失需求？
- 多余功能？（YAGNI 违反）
- 误解需求？
- 边界情况未处理？
- Spec 中的 Scenario 是否被测试覆盖？

   - 期望: ...

   - 位置: 文件路径:行号

[如合规:]
覆盖度: 全部 N 条需求已验证
备注: [观察记录]
