# Auto-Goal Skill 第二轮深度优化分析

> 分析日期: 2026-04-15
> 基线版本: SKILL.md v2（185行，已含 Cynefin 域感知 + 假设驱动 + 弱信号检测等 P0/P1/P2 优化）
> 研究方法: 六维度并行探索（Claude Code 最新架构 + OpenAI Agent SDK 2025-2026 + 认知科学新维度 + 前沿 AI Agent 研究 + 系统论与韧性工程 + Prompt 工程前沿）× 交叉综合
> 目标: 找到第一轮分析未触及的深层结构性优化空间

## 1. 元诊断：第一轮优化遗留的结构性盲区

第一轮优化成功注入了 Cynefin 域感知、假设驱动行动、弱信号检测等认知框架升级。但六维度深度探索揭示了一个更深层的认识：**第一轮优化升级了"决策框架"，但没有触及"认知经济学"——即如何在有限资源下做出足够好的决策**。

### 1.1 六个结构性盲区

| # | 盲区 | 问题本质 | 为何第一轮未触及 |
|---|------|----------|-----------------|
| 1 | **无认知模式切换** | 所有任务走同一套 OODA 循环，差异仅在"深度1-4"。缺乏专家级的"识别即行动"模式 | 第一轮关注"做什么"（域路由），未深入"怎么想"（认知模式） |
| 2 | **无信息觅食经济学** | "探索"策略缺乏何时停、何时换方向的量化启发 | 第一轮关注策略类型，未深入策略内部效率 |
| 3 | **无意图持久化机制** | 延迟意图（"等这步完成后记得做X"）完全依赖上下文记忆，压缩后必然丢失 | 第一轮关注状态外化，未区分"状态"vs"意图" |
| 4 | **无推理结构指导** | 何时分支推理、何时对抗性自评、何时多角度验证——没有指引 | 第一轮关注执行框架，未触及推理策略 |
| 5 | **单层验证架构** | 验证分微/标准/深度，但都是"执行后检查"。缺乏独立的多层防御 | 第一轮关注验证精度分级，未考虑验证拓扑 |
| 6 | **指令自身的注意力拓扑** | SKILL.md 作为 prompt 本身的注意力分布未优化（Lost in the Middle 效应） | 第一轮关注内容质量，未关注内容的认知呈现效率 |

### 1.2 更深层的张力：赋能 vs 开销的帕累托边界

第一轮分析指出"指令 Token 效率"问题（P2），但只建议精简措辞。六维度研究揭示更本质的问题：

**每条指令都在 Anthropic prompt cache 的稳定前缀中占据位置**。Claude Code 的架构设计中，`SYSTEM_PROMPT_DYNAMIC_BOUNDARY` 将系统提示分为缓存友好的稳定前缀和动态后缀。SKILL.md 的全部 185 行都在稳定前缀中，但：

- 注意力研究证实 LLM 存在 **U 型注意力曲线**（Liu et al.）：首尾信息保持率远高于中间
- 当前 SKILL.md 将最关键的六字原则放在前端（好），但将同样关键的韧性机制和反模式警觉放在中间偏后（次优）
- 条件激活研究表明 "When X, do Y" 格式的触发式指令比无条件规则更高效

这意味着 SKILL.md 优化不仅是"说什么"的问题，更是**"信息在何处、以何种形式呈现"**的认知工程问题。

### 1.3 本轮分析的定位

| 维度 | 第一轮 | 本轮 |
|------|--------|------|
| 关注层 | 决策框架（做什么决策） | 认知经济学（如何高效认知） |
| 理论基础 | Cynefin, 主动推理, 元认知 | 信息觅食, RPD, 韧性工程, 注意力科学 |
| 优化方向 | 增加新机制 | 增强已有机制的效率 + 补全缺失维度 |
| 核心信念 | "每步行动都是假设检验" | "认知资源是有限的——做正确的事 AND 高效地做" |

## 2. 优化方向一：认知模式切换——从连续调节到离散跳变 [P0]

### 2.1 当前局限

SKILL.md 有"深度连续调节（1-4）"和 Cynefin 域感知路由。但这两者都是**连续频谱**上的调节——本质上都是"做同样的事，只是做多做少"。这忽略了一个关键认知科学发现：

**专家和新手的根本差异不是思考深度，而是思考模式**。

### 2.2 多维度支撑

**Recognition-Primed Decision Making（Klein, 1998）**：自然决策研究发现，消防指挥官、急诊医生等领域专家在 80%+ 的决策场景中**不比较方案**。他们的决策过程是：识别情境模式 → 生成一个行动方案 → 心理模拟该方案 → 模拟无缺陷则执行；有缺陷则修改方案（不是生成新方案）。只在极少数"什么模式都不匹配"的场景才进入比较式分析。

**生态理性（Gigerenzer, 2007）**：简单启发式在匹配的环境结构下不仅比复杂算法更快，而且**更准确**（less-is-more 效应）。关键不是"深想就更好"，而是"用匹配环境的认知工具"。

**CoALA 认知架构（Sumers et al., 2024）**：区分"内部动作"（推理、检索、规划）和"外部动作"（工具调用、环境改变）。建议先穷尽内部动作再提交外部动作——但 RPD 告诉我们，对于已知模式，内部动作应该极其简短。

**Claude Code 实践**：简单任务"应跳过规划直接执行"。OODA 的 Boyd 本人也强调 **Orient 是核心**——观察-导向的循环应极快，不应被流程拖慢。

### 2.3 优化方向

引入**双模式认知**：

| 模式 | 触发条件 | 认知过程 | 对应深度 |
|------|----------|----------|----------|
| **识别模式**（Recognition） | 情境匹配已知模式 | 模式识别 → 心理模拟 → 执行 | 深度 1-2 |
| **分析模式**（Analysis） | 无匹配模式 / 模拟发现缺陷 / 意外 | 完整 OODA + 假设检验 | 深度 2-4 |

**关键设计**：不是两个独立路径，而是**识别模式是默认，分析模式是升级**。触发升级的信号：
- 心理模拟暴露缺陷（"这个方案在 X 场景下会出问题"）
- 任务偏离已知模式（"这不像我见过的任何情况"）
- 弱信号触发（已有机制，可复用）

### 2.4 与现有设计的关系

这是对 Cynefin 路由的**内部深化**：Cynefin 回答"这是什么类型的问题"（外部分类），双模式回答"我应该怎样思考这个问题"（内部认知）。Clear 域默认用识别模式，Complex 域默认用分析模式，但可以互相切换。

## 3. 优化方向二：信息觅食经济学——给探索装上"油表" [P0]

### 3.1 当前局限

当前 Explore 策略的指引："在 sub-agent 中执行，只将摘要返回主上下文。交叉验证关键信息，标注置信度。停止规则：足够好的方案 / 连续无新信息 / 探索超总预算 30%。"

这些停止规则是**结果导向**的（"有没有找到足够好的"），但缺乏**过程导向**的觅食效率指引。结果是：agent 可能在低价值的信息源上花费过多时间，或者过早离开高价值源。

### 3.2 多维度支撑

**信息觅食理论（Pirolli & Card, 1999）**：人类在信息环境中的行为遵循与动物觅食类似的最优化模型。关键概念：
- **信息气味（Information Scent）**：线索暗示的信息价值预期。高气味 → 深入；低气味 → 转移
- **补丁模型（Patch Model）**：在当前信息源（补丁）中收益递减时，切换到新补丁的最优时机由 **边际收益 vs 切换成本** 决定
- **信息饮食（Information Diet）**：只消费回报率超过平均值的信息源

**认知行动（Kirsh & Maglio, 1994）**：区分两类行动：
- **实用行动（Pragmatic）**：直接推进目标（写代码、修 bug）
- **认知行动（Epistemic）**：简化问题空间、降低认知负荷（写临时测试理解行为、打印中间状态、画依赖图）

当前 SKILL.md 隐含假设所有行动都是实用行动。但**认知行动是合法且必要的投资**——它们看似"不产出"，实则降低后续行动的错误率。

**注意力作为资源分配（Attention Economics）**：认知能力有限。非注意盲视（Inattentional Blindness）导致 agent 在深度聚焦时错过关键信号。需要**刻意的外围感知检查点**。

### 3.3 优化方向

给探索策略增加**觅食启发式**：

1. **气味跟踪**：进入信息源前评估其气味（相关性信号）。气味弱 → 快速扫描即离开；气味强 → 深入
2. **递减感知**：在同一信息源中，信息增益连续下降时果断切换（不是"没有新信息"才停——是"新信息的速率在下降"就该考虑切换）
3. **认知行动预算**：明确认可"为理解而做的探索性行动"是合法投资，非浪费。但设上限（不超过当前阶段 20% 的时间）
4. **外围扫描**：每 N 步执行一次广角扫描——是否有被忽略的信号？是否偏离了原始目标？

### 3.4 与现有设计的关系

这是 Explore 策略的**内部升级**，同时与弱信号检测（Sense）互补。弱信号检测是"被动发现异常"，外围扫描是"主动寻找盲区"。

## 4. 优化方向三：意图持久化与漂移防御 [P0]

### 4.1 当前局限

当前 SKILL.md 有完整的状态外化架构（state.md / decisions.md / observations.md / reflections.md）。但这些都是**回顾性记录**——记录"发生了什么"和"决定了什么"。

缺少的是**前瞻性意图管理**——"打算做什么"和"什么时候该想起做什么"。

典型丢失场景：
- "重构完这个函数后，需要更新所有调用方的测试" → 压缩后丢失
- "这个临时配置改动在提交前必须还原" → 5步后遗忘
- "用户提到的那个边界情况，最后需要专门验证" → 被后续任务淹没

### 4.2 多维度支撑

**前瞻记忆（Prospective Memory）**：记忆研究区分回顾记忆（记住过去的事）和前瞻记忆（记住将来要做的事）。前瞻记忆失败是日常认知错误的主要来源——不是"忘了怎么做"，而是"忘了要做"。

解药：**外化所有延迟意图**。认知科学称之为"实现意图"（Implementation Intentions, Gollwitzer 1999）——格式为 "When situation X arises, I will do action Y"。这种格式比模糊的"记住要做X"有效得多。

**目标漂移（Goal Drift）**：多轮规划研究（Multi-turn Planning）发现 LLM agent 的核心失败模式之一是**被子问题吸收**——投入大量时间解决某个子问题，不知不觉中偏离了原始目标。

解药：**周期性目标重申**。每 N 步重述顶层目标，检查当前工作是否仍在目标路径上。

**Ralph Wiggum 模式（Anthropic, 2025）**：Claude Code 的自主循环采用"无状态重采样"——每次迭代重置上下文，仅通过文件系统和 git 传递状态。这意味着**任何仅存在于上下文中的意图都会丢失**。意图必须被外化为可恢复的工件。

### 4.3 优化方向

1. **意图队列**：在 state.md 中增加 `## 延迟意图` 区域。格式：`When [触发条件], do [行动]`（Implementation Intentions 格式）
2. **检查点触发**：每个阶段边界自动检查意图队列——有触发条件满足的意图吗？
3. **目标重申节奏**：每 5 步 / 每个阶段切换时，重述顶层目标并检查漂移
4. **意图与压缩保护**：将"延迟意图"加入压缩保护清单

### 4.4 与现有设计的关系

这填补了记忆架构的**前瞻维度**。当前四个文件（state/decisions/observations/reflections）对应 OODA 的四个认知功能，但都是回顾性的。意图队列增加了第五个维度——Decide 的前瞻性延伸。

## 5. 优化方向四：假说竞争驱动的诊断——从反思到溯因 [P1]

### 5.1 当前局限

当前 Reflect-then-Retry 机制在**失败后**触发，流程是：失败现象 → 根因分类 → 暴露隐藏假设 → 修正策略 → 重试。这是有效的，但有两个盲区：

1. **单假说偏差**：反思过程倾向于生成一个"最可能的原因"然后修正，而非生成多个竞争假说并系统排除
2. **仅在失败后触发**：对于"结果不是错误但很意外"的场景（意外的成功、意外的副作用），没有诊断机制

### 5.2 多维度支撑

**溯因推理（Abductive Reasoning, Peirce）**：与演绎（从规则推结果）和归纳（从样本推规律）不同，溯因推理是"从惊人观察推最佳解释"。过程：
1. 观察到令人惊讶的事实 C
2. 如果假设 H 为真，则 C 是预期之中的
3. 因此有理由暂时采纳 H 并进一步检验

关键：**生成多个竞争假设，优先检验最可测试的那个**（而非最可能的——因为"最可能"的判断本身可能有偏差）。

**Agent-as-Judge 模式（前沿 AI Agent 研究）**：完成方案后切换为"怀疑论评审者"角色。不是评分，而是"具体哪里会出问题？"——定性的破坏性思考比量化评分更有效。

**认知灵活性理论（Spiro, 1988）**：在非结构化领域，有效表现需要**从多个视角重新表征知识**。当一个熟悉的模板在新语境中失败时，不要重试相同模板——从替代框架重新分析。

### 5.3 优化方向

将 Reflect-then-Retry 升级为**溯因诊断 + 结构化反思**：

1. **触发扩展**：不仅失败触发，"令人惊讶的观察"（意外结果、意外成功、意外副作用）也触发诊断
2. **多假说竞争**：遇到意外时，生成 2-3 个竞争假设，按可测试性排序，优先检验最容易证伪的
3. **视角切换**：修正策略前，从至少一个替代框架重新审视问题（"如果这不是 X 类型的问题，而是 Y 类型呢？"）
4. **审判者模式**：关键产出完成后，切换为怀疑论评审者——"具体在哪里、在什么条件下这会失败？"

### 5.4 与现有设计的关系

这是 Reflect-then-Retry 的**认知升级**。从"失败后的线性反思"变为"意外驱动的多假说竞争诊断"。同时与终态证伪（"什么条件下会失败？"）形成配合——终态证伪是对最终结果的审判，溯因诊断是对过程中意外的持续探究。

## 6. 优化方向五：多层独立防御——从验证分级到瑞士奶酪 [P1]

### 6.1 当前局限

当前验证架构：微验证（低风险）/ 标准验证（中风险）/ 深度验证（高风险）。这是**单层的精度调节**——本质上是"同一个检查做多深"。

问题在于：单层验证的失败率叠加后可能很高。如果每层验证有 10% 的漏检率，三个独立层能把漏检率降到 0.1%（`0.1 × 0.1 × 0.1`），但一层做三遍还是 10%。

### 6.2 多维度支撑

**瑞士奶酪模型（Reason, 1990）**：事故发生在多层防御的漏洞恰好对齐时。单层防御不可靠——安全来自**独立的多层防御**。关键词是"独立"——如果多层检查基于相同逻辑，漏洞会系统性对齐。

**Guardrails + Tripwires（OpenAI Agent SDK）**：输入/输出护栏作为**并行验证器**运行（不是顺序阻断器）。失败触发 tripwire 异常，立即中止。这是独立于 agent 主逻辑的外部检查。

**正常事故理论（Perrow, 1984）**：紧耦合 + 交互复杂的系统会产生不可预见的失败。增加冗余有时反而增加复杂度和新失败模式。启示：防御层应**松耦合**——各层独立失败不应引发新问题。

**熔断器模式（Failure Taxonomy, AI Agent 研究）**：迭代限制、上下文预算、目标漂移检查点——这些是**结构性约束**，不是检查逻辑。它们防止的不是"做错"，而是"做太多/太久/偏太远"。

### 6.3 优化方向

从"一层做多深"变为"多层独立防御"：

| 防御层 | 检查什么 | 何时 | 独立性 |
|--------|----------|------|--------|
| **规划审查** | 计划是否合理、完整、有遗漏 | 规划完成后 | 基于 Pre-mortem（已有） |
| **执行前门卫** | 即将执行的动作是否安全、可逆、在范围内 | 每步执行前 | 基于操作类型分类（已有） |
| **执行后验证** | 结果是否符合预期 | 每步执行后 | 微/标准/深度（已有） |
| **熔断器** | 是否超出结构性边界 | 持续监控 | 迭代计数、上下文消耗、目标漂移（**新增**） |

关键新增是第四层——**熔断器**（Circuit Breakers）：
- **迭代限制**：同一子问题重试超过 N 次 → 升级策略或求助
- **上下文预算**：探索消耗超过阶段预算 → 强制压缩或切换策略
- **目标漂移检测**：每 5 步检查"当前工作是否仍在顶层目标路径上"

### 6.4 与现有设计的关系

这不替换现有验证分级，而是在其基础上增加**正交防御维度**。现有验证解决"做对了吗？"，熔断器解决"是否偏了/卡了/超了？"

## 7. 优化方向六：成功解剖与启发式积累——Safety-II [P1]

### 7.1 当前局限

当前 reflections.md 的设计偏向**病理学**——主要记录失败分析、根因诊断、修正策略。虽然第一轮优化增加了"记录反直觉成功"，但这只是 Reflect-then-Retry 流程的附属条目（第7条），不是一等机制。

结果是：agent 只从失败中学习，不从成功中提取可复用的启发式。

### 7.2 多维度支撑

**Safety-II / 韧性工程（Hollnagel, 2014）**：Safety-I 研究"为什么出错"。Safety-II 研究"为什么通常是对的"。日常成功不是因为遵循了规则，而是因为持续的**适应性调整**——这些调整是隐性的，不被记录，因此无法被复制。

**生态理性（Gigerenzer）**：领域专家积累的不是通用分析能力，而是**匹配特定环境结构的启发式**。这些启发式是从成功经验中提取的，不是从失败教训中提取的。

**程序性记忆**：技能习得的核心是将"刻意的分析过程"转化为"自动的启发式"。这需要**成功经验的反复识别和编码**。

### 7.3 优化方向

1. **成功解剖**：复杂任务成功完成后，捕获"哪些适应性调整使其成功"——不是"做了什么"（那在 git log 里），而是"在哪些关键节点做了什么非显然的判断"
2. **启发式提取**：从反复出现的成功模式中提取可复用的 heuristics（如"当 X 类型的探索超过 3 分钟没有进展时，切换到 Y 策略总是有效的"）
3. **reflections.md 双面化**：不只是 "Failures & Root Causes"，而是 "Failures & Root Causes + Successes & Key Adaptations"
4. **跨会话沉淀**：任务结束时，有价值的启发式通过 memory 系统持久化

### 7.4 与现有设计的关系

这是将 reflections.md 从单面（失败学习）升级为双面（失败学习 + 成功提取）。同时与 memory 系统形成协同——reflections.md 是任务级学习，memory 是跨会话级学习。

## 8. 优化方向七：推理结构的情境选择 [P1]

### 8.1 当前局限

当前 SKILL.md 指导 agent **做什么**（澄清、探索、规划、执行、试探）和**如何验证**（微/标准/深度），但不指导**如何推理**。推理结构——何时线性思考、何时分支探索、何时多角度验证、何时对抗性审查——完全留给模型隐式决定。

### 8.2 多维度支撑

**思维树（Tree of Thoughts, Yao et al.）**：在离散选择点生成多个推理分支，评估后择优。适合：存在不可逆选择点的问题。不适合：线性执行类任务（3-10x 开销）。

**自洽性（Self-Consistency, Wang et al.）**：对同一问题从多个角度推理，取共识。当多角度收敛 → 高置信；发散 → 信号——需要深入调查。

**Constitutional Self-Critique**：生成 → 按原则审查 → 修正。当输出需要满足多个约束时特别有效。

**内心独白（Inner Monologue）**：在接收观察和执行行动之间插入结构化自言自语。桥接"感知"和"行动"——跳过它会导致反应性的脆弱行为。

**前沿 AI 研究的元模式**：15种推理模式聚类为三个关注点——(a) **搜索宽度**（ToT, GoT, 自洽性）、(b) **质量控制**（自我批判, Agent-as-Judge）、(c) **状态管理**（记忆、世界模型、内心独白）。**最高杠杆的启发式是知道当前时刻哪个关注点占主导**。

### 8.3 优化方向

增加**推理模式选择**指引（不是完整的推理算法描述，而是简洁的启发式）：

| 情境 | 推理策略 | 理由 |
|------|----------|------|
| 面临不可逆选择 | 生成 2-3 个备选方案，评估后决策 | 分支探索降低选错风险 |
| 关键判断置信度低 | 从 2-3 个不同角度推理，检查是否收敛 | 发散是信号，收敛是确认 |
| 输出需满足多约束 | 生成后按约束逐条审查，修正 | 生成时难以同时满足所有约束 |
| 接收到意外反馈 | 先叙述"学到了什么、计划如何改变"再行动 | 内心独白桥接感知与行动 |

### 8.4 与现有设计的关系

这是 OODA 循环 Decide 阶段的**内部丰富**。当前 Decide 说"选择策略 + 调节深度 + 设定验证标准"，但只涉及"做什么"的策略。推理模式选择增加了"怎么想"的策略维度。

## 9. 优化方向八：环境即协调层——深化stigmergy设计 [P2]

### 9.1 当前局限

当前记忆架构（`.tasks/auto-goal-{id}/`）被定位为"记忆"——agent 写给自己看的状态文件。但 Claude Code 最新架构和系统论研究揭示了一个更深的设计原则：

**文件系统不是备份记忆，而是主要的协调机制。**

### 9.2 多维度支撑

**Stigmergy（间接协调）**：蚂蚁通过修改环境（信息素痕迹）协调行为，而非直接通信。类比：agent 的状态文件、修改的代码、git 历史就是"信息素"——未来的会话/agent 通过解读这些工件来协调。

**Ralph Wiggum 模式（Anthropic, 2025）**：Claude Code 的自主循环采用无状态重采样——每次迭代完全重置上下文，仅通过文件系统和 git 传递状态。含义：**任何仅存在于上下文中的信息，在下一次迭代中都不存在**。

**文件系统作为状态总线（Claude Code 架构）**：sub-agent 将结果写入文件而非返回大负载到父上下文。文件系统是 agent 间持久协调的层。

**自创生（Maturana & Varela）**：活系统通过过程维持自身，而非通过静态结构。状态文件不是"写一次读多次"的存储，而是需要**持续维护**的活文档。

### 9.3 优化方向

1. **为陌生读者而写**：状态文件应设计为"一个完全没有上下文的新 agent 能理解并继续工作"，而非"提醒自己上次做到哪里了"。这是根本性的设计视角转变
2. **环境工件自解释**：每个外化的工件（状态文件、临时脚本、配置修改）都应包含足够的上下文让任何后续 agent 理解其目的
3. **活性维护**：每次恢复时，不只是"读取状态"，而是"重建理解并验证状态是否仍然准确"（当前的"信任但验证"已部分覆盖，可以更显式）
4. **上下文独立性原则**：核心假设从"上下文可能被压缩"升级为"上下文可能完全丢失"——所有关键信息都必须在文件系统中有副本

### 9.4 与现有设计的关系

这不改变记忆架构的结构，而是改变其**设计理念**。从"自己的笔记本"变为"团队的交接文档"。同时与上下文工程的"外化"策略协同——外化不只是"保存以防丢失"，而是"写给下一个 agent"。

## 10. 优化方向九：韧性三态模型——超越优雅降级 [P2]

### 10.1 当前局限

当前韧性机制：信息分级 + Reflect-then-Retry + 优雅降级（L0→L3）。降级是**单向的**——从高到低。但现实中，agent 面对压力时不止是"做更少"，还可能需要"做不同的事"甚至"重新定义问题"。

### 10.2 多维度支撑

**吸收-适应-转化三态模型（Resilience Theory）**：
- **吸收（Absorption）**：在现有参数内处理冲击。→ 重试、回退、使用备选方案
- **适应（Adaptation）**：调整参数以应对变化。→ 切换策略、重新规划、改变工具选择
- **转化（Transformation）**：改变系统本身。→ 认识到当前框架不够用，需要根本重构

**优雅延展性（Graceful Extensibility, Woods）**：不是"做更少"（降级），而是"超越设计条件的能力"。当标准方法触及边界时，**重构方法**（分解、外化状态、委托）而非均匀降低质量。

**延伸系统定律（Woods）**：系统总在能力边界运行。增加资源不会创造余裕——它会被新需求吸收。含义：不要为"足够的上下文"设计，要为**永恒的稀缺**设计。

**暗债务（Dark Debt）**：隐藏在正常运行下的假设和依赖，只在压力下暴露。定期审计 skill 设计中的隐式假设（"用户总是提供 X"、"工具总是成功"、"状态文件总是一致"）。

### 10.3 优化方向

将"优雅降级"升级为**韧性三态响应**：

| 韧性模式 | 触发条件 | 响应 | 示例 |
|----------|----------|------|------|
| **吸收** | 可预见的挫折 | 重试/回退/备选方案 | 工具调用失败 → 换工具或重试 |
| **适应** | 策略失效但目标不变 | 切换策略、重新规划 | 直接修改方案失败 → 转为测试驱动开发 |
| **转化** | 框架本身不适用 | 重新定义问题、升级给用户 | 发现需求理解根本错误 → 回到澄清 |

**关键规则**：每个模式有阈值——不在吸收循环中卡死（当前"3次反思后升级"部分覆盖），适应失败后要能跳到转化。

### 10.4 与现有设计的关系

这是优雅降级（L0→L3）的**认知升级**。L0→L3 关注"交付什么"（完整→核心→部分→分析），三态模型关注"如何应对"（同参数→换参数→换系统）。两者可以共存并互相补充。

## 11. 优化方向十：指令架构——注意力拓扑优化 [P2]

### 11.1 当前局限

SKILL.md 的 185 行内容在信息质量上已经很好，但作为 prompt，它的**认知呈现效率**未被优化。

### 11.2 多维度支撑

**Lost in the Middle（Liu et al., 2023）**：LLM 对长上下文的注意力呈 U 型分布——开头和结尾的信息保持率显著高于中间。对于 185 行的 prompt，中间 60-120 行区域是"注意力洼地"。

**Prompt 缓存架构（Anthropic）**：前缀缓存要求前缀完全不变才命中。动态内容（当前任务、运行时状态）必须在缓存前缀之后。支持最多 4 个缓存断点，最小可缓存长度 1024 tokens。

**条件激活（Meta-prompting 研究）**：LLM 对 "When X, do Y" 格式的触发式指令响应更好。XML 分区标签提升了条件激活的精度。

**具体性 vs 抽象性的二元策略（Prompt 研究）**：
- **具体规则**：对明确定义的行为（格式、安全约束）合规率更高
- **抽象原则**：对新场景泛化能力更强
- 最佳策略：**决策哲学用原则，行为约束用规则**

### 11.3 优化方向

**层级 1：位置优化**

```
行 1-15:   身份 + 核心信念 + 不可违背的约束     ← 注意力峰值区（首部）
行 15-40:  六字原则 + 域感知路由                  ← 高保持区
行 40-80:  OODA 循环 + 策略工具箱                 ← 稳定参考区（中部）
行 80-120: 上下文工程 + 韧性机制 + 记忆架构       ← 查阅式内容（可条件激活）
行 120-150: 介入模式 + 反模式                     ← 尾部注意力回升区
行 150+:   当前任务注入点                          ← 最近邻效应（紧贴对话）
```

**层级 2：条件激活**

将情境性指引从无条件陈述改为触发式：
- 当前："验证失败时，不直接重试，先结构化反思"
- 优化后："When 验证失败 → 先结构化反思再重试"（trigger-action 格式）

**层级 3：双策略指令**

- 抽象原则（六字、核心信念）保持原样——用于新场景泛化
- 操作规则（验证流程、降级阈值、熔断器）使用具体指令——用于确定性行为

### 11.4 与现有设计的关系

这是**元层优化**——不改变内容说什么，而改变内容如何被呈现和处理。与缓存友好布局（第一轮 P3）协同，但深入到注意力分布层面。

### 12.3 实施建议：两波推进

**第一波：认知效率升级（不增加结构，增强机制）**

这三个 P0 + 两个 P1 的共同特点：**可以通过修改/增强现有描述实现，无需新增独立章节**。

1. 在 OODA 循环的 Act 描述中增加**双模式提示**（识别模式 vs 分析模式）
2. 在 Explore 策略中增加**觅食启发式**（气味跟踪、递减感知、认知行动预算）
3. 在 state.md 结构指引中增加**意图队列** + 在循环中增加**漂移检查点**
4. 在 Reflect-then-Retry 中增加**溯因诊断**元素（多假说、可测试性排序）
5. 在 Observe 描述中增加**熔断器**规则

预期效果：
- 探索效率提升（不再在低价值源上消耗时间）
- 简单任务执行速度提升（识别模式跳过完整分析）
- 延迟意图不再丢失（外化到文件系统）
- 诊断质量提升（多假说竞争 vs 单假说修正）
- 失控循环被结构性截断（熔断器）

**第二波：设计理念升级 + 元层优化**

1. 推理结构情境选择（Decide 阶段扩展）
2. 成功解剖（reflections.md 双面化）
3. 环境即协调层（记忆架构设计理念升级）
4. 韧性三态模型（降级机制升级）
5. 指令架构注意力优化（需要 SKILL.md 结构性重排）

预期效果：
- 推理质量提升（情境化推理策略选择）
- 学习从单面（失败）变为双面（失败+成功）
- 跨会话协调质量提升（为陌生读者而写）
- 韧性从线性降级变为多维响应
- 指令处理效率提升（注意力热区放置关键内容）

### 12.4 核心约束（优化的边界）

延续第一轮的约束，补充新认识：

1. **赋能胜过补偿**：新增的是"认知工具"和"启发式"，不是"详细流程"
2. **简原则不可违背**：185 行已接近帕累托边界。新增内容必须通过"等量替换"或"增量极小"实现——**每增一句必须证明其价值超过所有现有句中最弱的一句**
3. **通用性优先**：认知模式切换、信息觅食、意图管理——这些对任何目标类型都适用
4. **Token 预算硬约束**：目标 ≤ 195 行。任何超出必须有对应删减
5. **新增约束——可观察性**：优化效果应可通过真实任务执行中的行为变化来观察。如果实施后 agent 行为无可辨识的变化，该优化不值得其 token 成本

## 13. 元反思：优化的递归困境与解药

### 13.1 第二轮优化面临的独特挑战

第一轮优化从"无域感知"到"有域感知"，从"无假设驱动"到"有假设驱动"——这是**0→1 的质变**，收益显著。

第二轮优化面临的是**1→1.2 的增量改进**。信息觅食启发式、溯因诊断、熔断器——每个单独看都有价值，但**聚合后的注意力稀释风险是真实的**。

这就是 prompt 优化的递归困境：**每条帮助思考的规则本身也消耗思考资源**。第一轮分析（§8.1）已指出这一点，第二轮的实际操作必须直面它。

### 13.2 解药：原则融合而非规则叠加

本轮的 10 个方向不应以 10 条新规则的形式注入。更好的策略：

1. **融入现有描述**：大多数方向可以通过增强现有段落的 1-2 句来实现，而非新增独立章节
2. **概念压缩**：多个相关概念压缩为一个精炼表达。如"信息觅食 + 认知行动 + 外围扫描"可压缩为"探索时跟踪气味、感知递减、周期性广角扫描"
3. **触发式呈现**：能用 "When X, do Y" 表达的不用无条件陈述
4. **删减换新增**：每增一句新内容，审视是否有已被更好覆盖的旧内容可以删减

### 13.3 一个更深的问题：skill 的生命周期

两轮优化后，SKILL.md 已经高度成熟。继续在 prompt 层面微调的边际收益在递减。

更高杠杆的优化可能在**runtime 层面**——不是改变 prompt 说什么，而是改变 prompt 如何被加载和使用：
- **渐进加载**：根据任务阶段动态注入相关 skill 片段（Claude Code 的 Skills 框架已支持这种模式）
- **运行时自适应**：基于任务特征动态调整 skill 的激活部分
- **经验驱动演化**：基于实际任务执行的成功/失败模式，自动调整 skill 权重

这些超出了当前"修改 SKILL.md"的范围，但标示了下一个优化前沿。

### 13.4 诚实的局限声明

本分析的局限：
1. **理论→实践鸿沟**：信息觅食理论在人类实验中验证充分，但在 LLM 上的映射是启发性的，不是精确的
2. **交互效应未知**：10 个优化方向之间可能存在交互效应（互相增强或抵消），无法在分析阶段预测
3. **Token 效率的精确度量缺失**：哪条指令真正改变了行为 vs 只是占了 token 位置，需要 A/B 测试才能确定
4. **模型依赖性**：这些优化针对当前模型能力水平。随着基础模型升级（更好的内置规划、更长的上下文、更强的自我监控），部分外部指引可能变得冗余

最稳健的策略保持不变：**一次改一个方向，观察效果，保留有效的，回退无效的。**
