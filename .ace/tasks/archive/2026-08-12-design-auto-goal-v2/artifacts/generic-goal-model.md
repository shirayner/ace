# 任意通用目标的领域无关建模

> 结论先行：一个目标不是"要做的事"，而是**被主张的世界差量 + 判定它是否发生的检验**。而 Agent 能做的只是 `目标 ∩ 授权可达能力`。把这两者显式分离，并把终态从**判据台账机械推导**而非由模型自述，就能同时消解软件工程偏见、静默缩范围、假 DONE 三个结构性缺陷。
>
> 本文只建模，不改代码，不预设 V2 目录结构。

---

## 0. 方法与限制

- **正向约束**：领域无关、不预设"可执行"、不使用固定问卷。
- **反向约束**（本文主动对抗的偏见）：把"能编辑文件 + 能读回 + 有二值测试"当成默认世界。软件工程恰好是三个能力都拉满的**特例**，任何以它为原型的模型迁到别的领域都会静默失效。
- **本次限制**：`WebSearch/WebFetch` 在本会话返回 API 422，外部一手实践资料未由本 worker 取证；下述模型为一阶推导 + 输入材料批判性采纳，凡引用业界方法处均标注为"待另路 worker 交叉验证"。
- 输入材料 `需求澄清经典方法论.md`、`需求理解与澄清方法论.md` 已通读，采纳/否决见 §9。

## 1. 三条正交轴：一切领域差异的最小解释

绝大多数"通用目标 Agent"失败，是因为把三件独立的事糅成了一件"能不能做完"。

| 轴 | 问题 | 缺失后果 |
|---|---|---|
| **可达性 Reachability** | 我有机制去改变目标物吗？ | 不能行动 → 只能交付计划/草稿 |
| **可观测性 Observability** | 行动之后我能独立读回世界状态吗？ | 能行动但不能自证 |
| **可判定性 Decidability** | 就算读回了，判据本身有真值条件吗？ | 读回也无法定论（好/美/动人） |

领域画像（同一模型的不同参数，不是不同流程）：

| 领域 | 可达 | 可观测 | 可判定 | 结构性风险 |
|---|---|---|---|---|
| 软件变更 | 高 | 高 | 高（测试） | 无（这是特例） |
| 研究/分析 | 高（产出物） | 高 | **低**（结论对不对无本地判据） | 自造 rubric 自评 |
| 写作/创意 | 高 | 高 | **低**（判定权在人） | 把"写完"当"写好" |
| 批量文件/数据 | 高 | 高 | 中（可计数但"没搞坏别的"不可证） | 误识别目标集 |
| 外部系统操作 | **中/低**（凭证、限流、UI） | **低**（只有自己的 trace） | 中 | 用"我发了"冒充"它生效了" |
| 线下/社会性目标 | **低**（须人做） | 低 | 低 | 静默把目标换成"写了封邮件" |
| 学习类目标 | 高（材料） | **无**（用户脑内） | 低 | 交付材料 = 声称学会了 |

**推论**：不需要为每个领域写一套流程。只需要让 Agent 在每个目标上**测出这三个轴的取值**，其余（该问什么、能到什么证据强度、终态是什么）都是从取值推导出的。

## 2. 目标模型：Goal 与 Mandate 分离

### 2.1 Goal（世界差量，与 Agent 无关）

```yaml
goal:
  intent: 追求的世界差量（必须表述为"世界变成什么样"，不是"做什么动作"）
  subject: 被作用对象 —— 必须能解析到唯一指称（见 §5.4 误识别）
  principals:
    owner:    目标归属人
    decider:  能改范围/批准取舍的人
    acceptor: 有权判定"算完成"的人（可以不是 owner；判定型判据下不可能是 Agent）
  criteria: [ Criterion ]          # 见 §3，带类型
  constraints: [ 全程必须成立的不变量：不得破坏X / 不得花钱 / 不得外泄Y ]
  scope: { in: [], out: [], deferred: [], external_dependency: [] }
  horizon: 差量须在何时成立；判定是否落在本次会话窗口内
  scope_version: N                 # 范围每次变更 +1，且须 decider 同意
```

要点：
- `intent` 强制写成差量而非动作，是"方案伪装需求"的结构性解药。"做个批量导入"不是 intent；"运营不再需要每天手工录入 2 万条"才是。
- `out` 与 `in` **同权必填**：只写 in 的范围不是范围。
- `scope_version` 是后面 §6 判定 DONE 的锚：DONE 只对**被批准的那一版范围**成立。

### 2.2 Mandate（Agent 侧的能力与授权）

能力不是一个布尔值，拆成五个独立可缺失的分量：

| 分量 | 含义 | 缺失时的正确终态 |
|---|---|---|
| **Effector** 效应器 | 存在从 Agent 通往目标物的改变机制（工具/API/文件系统/人作为中介） | 无 → 重定范围为"可达前缀"（§4）或 BLOCKED |
| **Access** 通路 | 在该效应器上的凭证/权限 | NEEDS_INPUT（凭证） |
| **Authority** 授权 | 主体允许把它用于此事（与 Access 正交：有密码 ≠ 有授权） | NEEDS_INPUT（批准）／政策禁止则 BLOCKED |
| **Competence** 胜任 | 用该效应器能做对（技能/知识，非权限） | 有界重试后 BLOCKED（并质疑前提） |
| **Observation** 观测 | 行动后能独立读回 | 可能 UNVERIFIABLE（§6） |

### 2.3 核心等式

```text
attainable = goal ∩ mandate
residual   = goal \ mandate
```

- 若 `attainable ⊂ goal`，这在**规划期**就是 PARTIAL，必须当场向 decider 披露，而不是执行到最后才"发现"。
- `residual` 必须被命名并作为**交接物**产出：需要人做什么、按什么顺序、需要哪些信息、如何验收。
- **静默替换是头号失效**：用户说"帮我退订健身房"，Agent 写了封邮件草稿然后报 DONE。合法形态只有一种——显式重定范围（"我不能操作该网站，我能做到的是 X，剩下 Y 需要你点这三步，是否按此推进？"）并取得同意。

这一个分解同时覆盖：线下目标、权限受限目标、"不可执行"目标、外部系统目标。不需要为它们各写一章。

## 3. 判据类型学：取代固定问卷的机制

判据不是自由文本，它有**类型**；类型决定(a)哪些追问是承重的 (b)最高能到哪一级证据 (c)谁有判定权。

| 类型 | 形态 | 判定权 | 证据上限 | 典型误用 |
|---|---|---|---|---|
| **State** 状态 | 某时点关于世界的命题（"订阅已取消"、"文件全部改名为 P"） | Agent 可判 | E2–E4 | 用"我执行了"代替读回 |
| **Behavior** 行为 | 系统在激励下的响应（须施加激励才可判） | Agent 可判 | E3 | 未施加激励就断言 |
| **Artifact-property** 产物属性 | 产出物的可核查属性（"覆盖 5 家竞品且每条有出处"） | Agent 可判（有明文标准时） | E3/E4 | 把"覆盖度"偷换成"字数" |
| **Judgment** 判定 | 满足性取决于人的评价（"动人"、"干净"、"专业") | **仅 acceptor** | E4 | **自造 rubric 自评**（研究/写作头号病） |
| **Effect** 效果 | 延迟/统计性结果（"流失降 5%"） | 需时间窗 | E5 | 在会话内声称达成 |
| **Knowledge** 知识 | 用户理解发生改变（学习类） | **仅用户**（自评/被检验） | E4 | 交付讲义 = 学会了 |
| **Negative** 否定 | "没有泄漏 PII"、"没搞坏别的" | 原则不可证 | **有界 E3** | 全称断言（假 DONE 温床） |

规则：
1. 每条判据必须在建模期贴上类型；**未贴类型的判据不得进入执行**。
2. `Judgment` / `Knowledge` 类判据若在本次没有可触达的 acceptor → 该判据终态是 UNVERIFIABLE，不是 DONE。Agent 无权自封 acceptor。
3. `Effect` 类必须做二选一并记录：转成前导代理指标（并声明它只是代理），或移入 `deferred`。
4. `Negative` 类必须重写为有界形式："已在 A/B/C 三处检查，未发现 X"——把全称改成明确的检查面。这是"永不假 DONE"的关键改写。
5. 模糊谓词（快、大量、及时、合理、实时、相关、异常）在**任何领域**都必须量化或降级为 Judgment 交还 acceptor。（采自输入材料 §六，是少数真正领域无关的部分）

## 4. 不可执行目标：可达前缀 + 交接物

不要把"不可执行"当异常，它是 `residual ≠ ∅` 的常态。统一处理：

```text
1. 沿 intent 找出最长的可达前缀（我确实能改变世界的那一段）
2. 为 residual 生成交接物：人类可独立执行的最小充分指令
3. 用 scope 事件把"目标 → 可达前缀 + 交接物"这次重定显式化，取得 decider 同意
4. 终态最多为 PARTIAL；若可达前缀为空，则 BLOCKED（附交接物，不空手而归）
```

例（社会性目标，"让房东修锅炉"）：可达前缀 = 整理故障事实与法条依据、起草分级沟通信、给出升级路径与时限；residual = 发送、通话、开门验收。终态 PARTIAL，判据类型是 Effect（锅炉被修）+ Judgment（信写得得体），两者都不可能在本次 DONE。

## 5. 风险、批准与不可逆性（领域无关）

### 5.1 别用工具名判风险

"危险 = rm/force push" 是软件偏见。真正的不变量是五个维度：

| 维度 | 提问 |
|---|---|
| **可逆性** | 我用同样的能力能撤销吗？代价是免费/昂贵/不可能？ |
| **外部性** | 效果是否离开用户私域（发送、发布、支付、通知第三方）？外部化的社会效果几乎从不可逆，即便技术上可删。 |
| **爆炸半径** | 影响多少实体？可枚举吗？ |
| **可撤窗口** | 是否存在一段可撤销的时间？ |
| **可感知性** | 出错时用户会察觉吗？**静默污染比响亮失败更危险**，应提高门槛。 |

批准门 = f(可逆性, 外部性, 爆炸半径)，不是 f(工具名)。

### 5.2 批准的性质

- **有范围**：批准针对"这个动作 × 这个目标集 × 这个时间窗"。
- **有记录**：记录**被批准的到底是什么**（原文 + 目标集枚举），而非"用户同意了"。
- **不传递**：一次批准不外溢到下一个实例、下一个目标。
- **抗漂移**：若实际动作在任一风险维度上偏离了被批准的描述 → **重新批准**（delta re-approval）。这是"之前对齐过了"的结构性封堵。
- **可预授权**：允许 standing consent，但必须带边界（类别 + 上限 + 失效条件）。

### 5.3 追问 vs 批准

两者不同：追问补的是**信息**，批准给的是**权力**。信息可由 Agent 自己找（则不该问）；权力只能来自 principal（则必须问）。

### 5.4 误识别：常被忽略的最大风险

作用在错的目标上，危害通常大于动作本身。任何高爆炸半径动作前：**先枚举将被影响的确切集合**，把枚举本身作为批准对象。（"批量改名"真正的风险不是改名，是改错目录。）

## 6. 证据阶梯与终态推导

### 6.1 证据阶梯（领域无关）

| 级 | 名称 | 内容 | 证明了什么 |
|---|---|---|---|
| E0 | 断言 | Agent 说做完了 | **什么都没有**（永不充分） |
| E1 | 行动痕迹 | 我执行了该动作的记录 | 证明**动作**，不证明**效果** |
| E2 | 独立读回 | 行动后重新观测世界状态 | 状态成立于此刻 |
| E3 | 派生检验 | 对观测状态施加规则/计算机械判定（测试、校验、计数、diff、明文 rubric） | 判据被机械满足 |
| E4 | 外部确认 | Agent 之外的权威确认（CI、审批人、对方回执、收据、acceptor 认可） | 判定权在位 |
| E5 | 世界效果 | 意图效果被度量（指标移动、锅炉真修好） | 差量真的发生 |

**E1→E2 是最常被跳过的一级**，也是"外部系统操作"类目标假 DONE 的唯一来源。

### 6.2 每条判据的状态

`SATISFIED / VIOLATED / UNTESTED / UNTESTABLE / MOOT(已移出范围)`

- 要求证据级 `required_rung` 由 §5.1 风险维度设定；判据类型给出 `max_rung`（§3）。
- `required_rung > max_rung` → 该判据 UNTESTABLE，且这件事必须在**规划期**就说出来。

### 6.3 终态定义

| 终态 | 定义 | 必带 |
|---|---|---|
| **DONE** | 在 `scope_version=N` 下所有 in-scope 判据 SATISFIED 且达到 required_rung；无 constraint 违反；范围未被静默收窄 | 每条判据的证据指针 + 级别 |
| **PARTIAL** | 一个**已命名**的非空子集 SATISFIED，且已交付部分**自身可用（coherent）**；余下部分有明确 next action 与责任人 | 已完成集 / 未完成集 / residual 交接物 |
| **BLOCKED** | 继续推进所需之物**当前无任何可触达行为者能提供**，计划必须改变 | 缺什么、试过什么、可选替代方向 |
| **NEEDS_INPUT** | 一旦 principal 给出**具体命名之物**（决策/凭证/批准/产物/事实）即可**原样恢复**同一计划 | 问题、为何阻塞、猜错代价、**不回复时的默认动作** |
| **UNVERIFIABLE** | 动作已执行且相信已达成，但判据类型或观测上限使其无法达到 required_rung | 已达到的**最高**级别 + 为何无法更高 + 谁能判定 |

关键判别：
- **BLOCKED vs NEEDS_INPUT 的分界不是"谁的错"，是可恢复性**。能被一句回答原样续跑 → NEEDS_INPUT；须改计划 → BLOCKED。
- **PARTIAL vs 不一致态**：若中断处的世界状态不自洽（半改坏），正确终态是 BLOCKED + 先回滚，**不是** PARTIAL。PARTIAL 要求已交付部分是可用前缀。
- **UNVERIFIABLE 不是借口态**：只有在证明已取得**最高可得级别**后才允许使用。否则那是 UNTESTED，属尽责失败，应报 PARTIAL 或 NEEDS_INPUT（去找 acceptor）。

### 6.4 优先级（冲突时的仲裁序）——刻意偏向少报

```text
1. constraint 违反 或 状态不自洽  → BLOCKED（先回滚）
2. principal 能给出钥匙           → NEEDS_INPUT（优先问，而不是停）
3. 任一判据未达 required_rung      → UNVERIFIABLE（永不上舍入为 DONE）
4. 范围曾因任何原因收窄            → PARTIAL（不因"我尽力了"变 DONE）
5. 全票 + 有证据 + 未静默收窄      → DONE
```

### 6.5 机械化建议（对控制面）

> **终态必须由判据台账计算得出，不得由模型自行撰写。**

台账逐条记录 `{criterion_id, type, required_rung, achieved_rung, state, evidence_pointer}`；终态 = 对台账施加 §6.4 的纯函数。这把"不许假 DONE"从劝告变成结构。同理，范围收窄必须是带 decider 同意的事件（`scope_version` 递增），DONE 只校验被批准的那一版——否则"先偷偷缩范围再宣布完成"仍然可行。

`FAILED`（尝试过、明确未达成、方案穷尽）在给定五态中无位置，本文映射为 `BLOCKED(reason=falsified)`；命名是否应独立，列为未决。

## 7. 不用固定问卷的追问机制

模型是**带默认值与敏感度的槽位集**，不是问题清单。

1. **槽位驱动**：每个槽位有 (a) 从上下文/惯例/先例推导的默认值 (b) 敏感度 = 取错值造成的代价 × 不可逆性。
2. **提问判据（双闭条件，须同时满足）**：
   - `不确定性 × 猜错代价 > 提问成本`，且
   - **答案只在 principal 脑中/手中**（不可由 Agent 自行查明）。
   第二条最常被违反：把自己能查的东西拿去问人，是把工作推给用户。
3. **以决策形式提问**：给 2–3 个选项 + 推荐 + 取舍代价，而非开放式提问。（"业务上允许异步吗？若允许我建议返回任务号"优于"接口怎么设计"）
4. **一次成批、按决策树排序**：后面的问题可能因前面的答案而失效。
5. **未问的槽位一律登记为假设**，带**defeat 条件**（什么现象出现就说明它不成立）。假设很便宜；**未记录的假设**才是事故源。
6. **惊讶测试兜底**：用户此刻看到这个决定会惊讶 → 问。
7. **有界**：追问在"已定位到可度量结果 / 已定位真实任务 / 再问只涉及不影响本决策的上层战略"处停止。

### 方法路由（按目标形状，不按领域）

| 形状信号 | 承重方法 |
|---|---|
| 目标被表述为方案 | 反推问题（差量重写 + 有界 5-why） |
| 规则密集、条件组合多 | 决策表穷举（正例/反例） |
| 判据是 Judgment 类 | **尽早取样**：给 1 个小样本让 acceptor 判，别整篇做完再问 |
| 领域不熟 | 先找 acceptor 的既有标准/先例，而非自造标准 |
| 高爆炸半径 | 先枚举目标集并就枚举取得批准 |
| 存在影子流程/人工补偿 | 还原现状再设计（低效步骤可能正承担风控职责） |

## 8. 领域探针：同一模型的六次实例化

| 目标 | 主判据类型 | Mandate 缺口 | 证据上限 | 最可能终态 | 特征失效 |
|---|---|---|---|---|---|
| 重构模块使其可测 | Behavior + Negative | 无 | E3 | DONE | Negative 判据写成全称 |
| 调研某市场并给建议 | Judgment + Artifact-property | 无 | E3(明文标准)/E4 | UNVERIFIABLE 或 PARTIAL | 自造 rubric 自评为 DONE |
| 写一封说服性的信 | Judgment | 无 | E4（须 acceptor） | UNVERIFIABLE | "写完了"当"写好了" |
| 整理 3000 个文件 | State + Negative | Authority（批量不可逆） | E2/E3 | DONE 或 NEEDS_INPUT(批准) | 误识别目标集 |
| 取消某网站订阅 | State | Access + Effector | E1（只有自己 trace）→ 需 E4 回执 | NEEDS_INPUT 或 UNVERIFIABLE | 用 E1 冒充 E2/E4 |
| 让房东修锅炉 | Effect + Judgment | Effector（须人做） | E5（超窗口） | PARTIAL（可达前缀 + 交接物） | 静默把目标换成草稿 |
| 学懂分布式共识 | Knowledge | 无 | E4（仅用户可判） | UNVERIFIABLE（除非用户自评/被检验） | 交付材料即声称达成 |

七行里只有第一行能自然到 DONE。**"多数通用目标的正确终态不是 DONE"** 本身就是设计前提；把 DONE 当默认目标的系统必然以假 DONE 收场。

## 9. 对输入材料的采纳 / 调整 / 否决

**采纳（确认领域无关）**
- 事实/解释/假设/决策四分 → 直接进入 §7.5 假设登记与证据阶梯（E0 之所以永不充分，就是它是"解释"冒充"事实"）。
- 目标/需求/方案三分 → §2.1 intent 强制写成差量。
- in/out 范围同权 → §2.1 scope 与 §6.3 静默收窄封堵。
- 模糊形容词必须量化 → §3 规则 5。
- "只有可验证的才算澄清" → 升级为本文核心：判据类型决定可验证性上限。
- "别把所有问题推给用户"（先自研候选方案，只把业务决策交出去）→ §7.2 第二闭条件。
- 反例验规则、对比迫使规则显性化 → §7 方法路由。

**调整**
- 十步澄清法：作为**顺序流程**否决（是固定问卷），其内核转为 §7 的槽位敏感度 + §7 路由表。
- 角色表（Sponsor/PO/…）：压缩为 owner/decider/acceptor 三个**功能位**；仅当三者分离时才追问。原表是企业软件语境的实例化。
- 5-why：保留但强制加终止条件（§7.7）。

**否决（软件工程局部知识，不进通用模型）**
- 非功能需求清单（性能/可用性/审计/兼容）—— 它是 State/Behavior 判据在软件域的**实例**，不是通用维度。写作、线下目标上机械套用会制造噪音。
- Given-When-Then —— Behavior 类判据的一种表达法，非唯一；State/Judgment 类硬套 GWT 会失真。
- "需求 = 九元组"清单式定义 —— 用 §2 的 Goal/Mandate 分离替代，因为它完全没有"执行者能力与授权"这一维，而这正是通用 Agent 的关键约束。

> 上述"业界方法"层面的判断待另一路 worker 用一手资料交叉验证（本 worker 的 WebSearch 不可用）。

## 10. 给 V2 的最小落地要求（不涉具体目录）

1. Goal 规格作为一次性 artifact 落盘；**criteria 台账**是独立的小型投影，逐条带 `type / required_rung / achieved_rung / state / evidence_pointer`。
2. 终态由台账纯函数推导，模型不得撰写终态；范围变更是需 decider 同意的事件，`scope_version` 递增。
3. 判据未贴类型 → 禁止进入执行；`required_rung > max_rung` 必须在规划期披露。
4. 批准记录"被批准的原文 + 目标集枚举"，并实现 delta re-approval 检测。
5. 五个终态各有强制字段（§6.3 右列），缺字段视为未报告；`NEEDS_INPUT` 必须携带"不回复时的默认动作"。
6. 任何终态都要产出 residual 交接物 —— "永不空手而归"由此从口号变为字段约束。

## 11. 未决问题
